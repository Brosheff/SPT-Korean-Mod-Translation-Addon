# 1.0.0 — 진단 저장 제거와 반복 처리 축소

클라이언트 1.0.0 / 서버 애드온 1.0.0. 번역 데이터는 수정하지 않았다.

## 진단과 로그

- 클라이언트 `mod-locales/reports`, F12 `_discovered-settings.json` 및 `_templates`, 서버 `reports/untranslated_direct_messages.json` 생성·갱신을 제거했다. 미적용 본문 목록, 스냅샷용 메타데이터 수집, 정렬·직렬화·해시 계산도 배포 코드에서 제거했다.
- 정상 실행은 클라이언트·서버 각각 로드 완료 한 줄만 남긴다. 일부 실패가 있으면 로드 요약에 경고 상태를 표시한다.
- 실제 JSON 거부, 설치된 모드의 패치 실패, 실행 중 원문 유지, 언어 동기화 실패는 짧은 경고/오류로 남긴다. 반복 경고는 고정된 문제 식별자로 억제하고 최대 512개까지 기억한다. 오류 상세 문자열도 길이를 제한한다.
- 기존 보고서를 자동 삭제하지 않는다. BepInEx와 SPT 자체 로그 및 다른 모드의 로그는 건드리지 않는다.
- PitFireTeam의 언어팩 복사는 실제 번역 기능이므로 유지한다. 모든 파일 쓰기를 일괄 차단한 것이 아니다.

## 성능 수정

- 클라이언트 번역 JSON은 Awake에서 한 번 읽고 로케일·UI에 공유한다. 상속된 match_mode는 지역 변수로 계산해 원본 프로필 행을 수정하지 않는다.
- 언어 조회 시점은 그대로 두고 부모 CurrentCulture 함수 호출을 delegate로 연결한다. 연결 불가 시 기존 리플렉션 호출로 돌아간다. 부모 내부 구현과 30프레임 주기는 유지한다.
- 카지노를 찾기 전에는 캔버스 콜백을 등록하지 않는다. 늦게 로드되는 Casino.Client를 발견하면 텍스트 갱신→폰트 보정 순서로 등록한다.
- 폰트 보정은 여전히 원본 UI 생성이 끝난 후 화면 렌더링 전에 한다. 같은 문구·실제 폰트·실제 머티리얼이 일치하면 글자 검사와 재대입을 생략한다. 원본 모드가 뒤에서 폰트를 바꾸면 다시 보정한다.
- 정상 사용 중 폰트 전체를 주기적으로 재검색하지 않는다. 지원 폰트를 찾지 못한 경우만 제한된 간격으로 재탐색하며 늦게 로드된 폰트도 정적인 라벨에 적용한다. 추적은 약한 참조를 사용한다.
- 임시 문자열/배열 없이 글자 지원을 검사한다. 영어 전환 복원과 애드온 종료 시 전용 머티리얼 정리를 유지한다.

## 검증

- 로케일 검사 176,806개: 현재 데이터 전체에서 이전 1.7.20 DLL과 새 배포 DLL의 한국어·한영병기 결과 비교, 공유 원본 행 불변성, 보고서 폴더 미생성, 오류 중복 억제를 포함한다.
- 카지노 검사 106개: 실제 Harmony 적용과 설치 Casino.Client의 46개 메서드/67개 대입 지점 감사. 같은 문구를 400회 처리해도 폰트 검색·글자 검사·재대입 증가 없음. 생성 함수의 폰트 재설정, 늦은 폰트 로드, 새 글자, 영어 복원 및 카지노 미설치/늦은 로드를 검사했다.
- 서버 검사 1,057개: 현재 메시지 번역과 미일치 원문 보존, 미번역 메일 수집 함수 제거 확인.
- 성능 검사는 반복 호출 계수와 파일 생성 여부 기준이다. 실제 FPS·인게임 화면은 확인하지 않았다. 과거 DLL은 개발용 별도 폴더에서만 비교했다.

## 유지보수 및 설치

상세 로케일 진단은 테스트 프로젝트의 LOCALE_DIAGNOSTICS 심볼에서만 메모리로 수집한다. 배포 DLL에는 포함하지 않는다. 문제 조사 목적으로 배포본에 자동 보고서를 다시 추가하지 않는다.

게임과 서버를 종료하고 클라이언트 DLL 및 서버 DLL을 함께 교체한다. 구형 번역 파일이 혼재한다면 기존 translations를 밖에 백업한 후 배포본의 104개 JSON 폴더로 교체한다. 사용자 편집본은 백업 후 필요한 변경을 별도로 반영한다. 게임 설치 경로는 이번 작업에서 수정하지 않았다.

언어 확인 빈도 축소, 서버 HTTP 비동기화, 새 번역 엔진 도입은 이번 범위에 포함하지 않았다.
