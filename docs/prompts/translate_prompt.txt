# Escape from Tarkov / SPT 모드 번역 프롬프트 — 1.7.14 이후 (2026-10-12 표기 갱신)

이 문서는 **현행 번역 문체 지침**이며 제목의 1.7.14는 도입 이력이지 현재 애드온 버전이 아니다. 이 문서는 번역 본문 작성 지침이다. 애드온의 `번역작업안내서.md`, `TRANSLATION_FORMAT.md`와 함께 읽는다. 과거 감사 자료는 `docs/records/audits/`에 별도 보존하며 필요할 때만 참고한다. 현재 버전은 프로젝트 파일과 실제 배포 산출물을 확인하며, 폴더명으로 버전을 판단하지 않는다.

> **작업 순서 지침:** 번역문을 작성하기 전에 `모드번역_작업절차.md`의 애드온 분석 → 대상 모드의 실제 화면 문자열 조사 → 필요시 분할 → 번역/훅 연결 → 최초 조사와 역대조 절차를 따른다. 이 프롬프트는 **어떻게 번역할지** 정하는 문서이며, JSON만으로 번역 적용이 끝났다는 뜻이 아니다. 별도의 `extras`·원본 모드 파일 수정으로 적용 경로를 우회하지 않는다. 회차 간 인계는 `번역대상_인계기록_양식.md`를 사용한다.

## 0. 현재 작업 기준 — 먼저 적용

- 최신 사용자 파일을 기준으로 한다. 예전 백업/배포본으로 되돌리지 않는다. 기존 확정 번역과 사용자가 지정한 용어를 우선한다.
- 기본 용어는 사용자가 제공한 `translation_terms_only_REBUILT` 등의 용어 파일을 참고한다. 해당 파일이 없으면 확인한 척하지 말고 현재 제공된 레퍼런스와 기존 번역을 사용한다.
- 바닐라 상인 말투는 제공된 상인 대사 자료를 확인한다. `docs/reference-data/vanilla_trader_dialogue_reference.json`은 SPT 4.0.13의 프라퍼·테라피스트·펜스·BTR 운전병 네 명만 담은 과거 참고 자료다. 나머지 화자는 현재 부모 로케일과 실제 대사를 확인한다. 원본 모드 자료는 사용자가 제공한 **현재 버전의 실제 모드 ZIP·프로젝트 파일**에서 확인한다. 별도 소스 저장소가 없거나 열리지 않으면 없는 자료를 열람한 것으로 주장하지 않고 경로·검증 수준을 `미확인`으로 기록한다.
- 번역 데이터의 `source`는 실제 원문이며 변경·trim하지 않는다. `translation`에는 번역 본문만 저장한다.
- **전체 원문의 괄호 병기, 설명 앞 `[원문 이름]`, 설명 끝 `(모드명)`은 사람이 번역문에 작성하지 않는다. 기존 코드가 표시 시점에 생성한다.** `translation_bilingual` 또는 `_bilingual` 필드를 새로 만들지 않는다.
- 기본값은 병기 없음이다. UI·F12·상인명·상인 소개·대사·알림·메일에 임의로 원문을 덧붙이지 않는다.
- `(50발)`, `(FMJ)`, 의미상 보충 설명, 원래 본문에 포함된 괄호는 보존한다. “괄호 병기 제거”는 모든 괄호를 지우라는 뜻이 아니다.
- 부모의 실제 규칙: 아이템 이름은 한영병기에서 줄바꿈 원문, 아이템 설명의 `[원문 이름]`은 두 언어 공통, 퀘스트 제목은 두 언어 공통 인라인 원문이다. 업적 등 다른 분류는 안내서의 확인된 규칙만 적용한다.
- 설명 끝의 모드명은 모드 아이템 식별용이므로 **한국어와 한영병기 모두** 코드로 표시한다. `mod_name` 한 곳에서 관리한다.
- 번역 추가는 기존 JSON과 적용 경로를 사용한다. 새 번역 엔진, 전역 UI 치환, 원본 모드 DLL 수정, 부모 데이터 수정으로 해결하지 않는다.
- 세력·조직 고유명은 아래 4-2절의 **확정 표기**를 사용한다. 특히 BEAR/USEC/RUAF/UNTAR는 번역 본문에도 영문 그대로 쓰며, 다른 지정 명칭만 표에 따라 음차한다. key/source/내부 ID는 바꾸지 않는다.
- 과거 `mods_scripts_add.json`, `_note_price`, 패처 실행파일 모드 목록, 데이터 두 벌 동시 편집은 현재 애드온의 작업 방식이 아니다. 사용자가 별도로 그 구형 패처를 요청한 경우에만 구형 프로젝트를 별도 조사한다.

## 🔹 1. 번역 원칙

1. **ID 검증**  
   - 원본 JSON 또는 실제 코드에서 정의·조회하는 키/ID를 확인한 뒤 번역한다.  
   - 임의로 새로운 ID를 만들거나 기존 ID를 수정하지 않는다.  
   - JSON에 키가 없더라도 코드가 실제로 주입·조회하는 locale 키라면 기존 `locale_additions` 등 지원 경로를 확인한다. 조회 지점이 없는 키는 만들지 않는다. 코드의 직접 표시 문자열은 5절에 따라 처리한다.  
   - `Description` 값이 `null`이면 번역하지 않고 그대로 건너뛴다.  

2. **Name 처리 규칙**  
   - 반드시 번역한다.  
   - 브랜드/제조사 이름은 **부분적으로 음차 허용**:  
     - 음차: 맥밀란(McMillan), 레밍턴(Remington), 맥풀(Magpul), 콜트(Colt), 어큐러시 인터내셔널(Accuracy International)  
     - 원문 유지 + 괄호 보충: PGW 디펜스, HK(헤클러 & 코흐), FN, KAC(나이츠 아르마먼트 컴퍼니), MDT  
   - 총기 모델명 및 탄종 규격은 원문 그대로 유지 (예: AR-15, AK-74M, 7.62x39mm).  
   - 군사용 용어는 한국어로 변환 (예: stock → 개머리판, barrel → 총열).  
   - 국제 약어(FMJ, HP, SP, AP 등)는 그대로 유지한다.  
   - 색상 약어(BLK, FDE 등)는 한국어로 변환한다.  
   - 탄약 아이템의 Name 값은 원문을 유지한다. source와 translation이 같으므로 표시 코드도 원문을 반복하지 않는다.
   - 탄창은 번역이 어떻든 장탄수,(반점포함) 이름 탄종 "탄창" 순서로 번역한다.
예시:
```json
"32발, 다니엘 디펜스 5.56 탄창"
"32발, 다니엘 디펜스 5.56 탄창 (사막색)"
"20발, 콜트 AR-15 5.56x45 직선형 탄창"
```

   - 탄약팩도 규칙이 있다. 탄구경_탄약명_"탄약 팩"_(발수) 순서로 정해서 번역하라.
예시:
"5447ac644bdc2d6c208b4567 Name": "5.56x45mm M855 탄약 팩 (50발)"

.300 blackout, .300 blk 등은 .300 블랙아웃으로 통일한다.

3. **ShortName 처리 규칙**  
   - 명사는 번역한다.
   - 탄약/탄약팩 ShortName은 원문 유지한다.
   - 브랜드, 고유명사 장비이름은 음차로 번역한다.
   - 접미사에 HG, rail, trigger 등의 장비명이 있으면 지우고 주어만 남긴다.
     다만 Thr, FS, RS, UHG, LHG, Upper, Lowwer, Side 등의 표기가 있을 경우 각각 나사산, 가늠쇠, 가늠자, 상부 총열덮개, 하부 총열덮개, 상부, 하부, 측면으로 번역한다.
   - 탄약종류, 탄약팩의 ShortName은 번역하지 않는다.
   - 브랜드/제품 이니셜, 전체 대문자 약어는 원문 유지한다. 세력명은 4-2절의 명시적 표기를 따른다.
     예: PMAG, MOE, CTR, SL-K, SL-M, QDC, CQB, MFR, MCMR, LEAP, SBR, CQBR, AK, AR, HK, SIG, KAC, BCM, DD, FDE, OD, BLK, GEN, MOD, FAST, MRO, APC, JPC, AVS 등.
   - 미분류 대상은 원문 그대로 유지한다.
   - 단위 표기는 한글화할 수 있다.
     예: 15" → 15인치
     예: 10" → 10인치
     예: 200mm → 200mm 유지

4. **Description 처리 규칙**  
   - 반드시 번역한다.  
   - 존칭체(“~합니다”, “~있습니다”)를 사용한다.  
   - 의역하지 않고 원문 의미를 충실히 보존한다.  
   - 군사용 용어는 한국어로 변환한다.  
   - 국제 약어는 한국어 풀어쓰기와 병기한다.  
     - 예: "FMJ" → "풀 메탈 재킷(FMJ)", "HP" → "할로 포인트(HP)"  
   - 브랜드명은 음차된 형태 또는 규칙에 맞춘 표기를 사용한다.  
   - 색상 약어는 한국어로 변환한다.

## 4. 퀘스트·상인 문장

- 퀘스트 제목의 translation에는 제목 번역만 쓴다. 원문과 괄호를 직접 붙이지 않는다. 단독 제목 키는 실제 퀘스트 정의로 확인한 뒤 `display_type: "quest_title"`을 지정한다.
- 퀘스트 정의의 traderId와 실제 표시 코드를 확인해 화자를 식별한다. description, startedMessageText, successMessageText, failMessageText 등이 의뢰인의 말이면 그 인물의 직접 발화로 번역한다.
- acceptPlayerMessage, declinePlayerMessage, completePlayerMessage 등 플레이어 응답 필드는 실제 화자를 확인해 플레이어 말투로 쓴다. changeQuestMessageText도 사용 지점을 확인한다. 필드 이름만으로 모든 메시지를 의뢰인 말투로 바꾸지 않는다.
- “○○와 관련된 의뢰입니다” 같은 제3자의 요약 설명으로 대체하지 않는다. 원문의 지시·평가·경고·은유와 상인별 어조를 유지한다.
- 목표는 `찾기`, `건네주기`, `설치하기`, `처치하기`, `생존 후 탈출`처럼 간결하게 쓴다.
- 퀘스트 목표는 두 언어 공통 `한국어 목표\n(영문 목표)`다. 1.7.15부터 실제 conditions의 ID와 연결한 행에 `display_type: "quest_objective"`를 지정한다. 설명/대사와 구분하고 `[대상 아이템]` 등 본문 강조를 보존한다. `translation`에 수동 원문을 저장하지 않는다. 과거 `QUEST_PATTERN_REAUDIT_20261003.md`는 제공되지 않으므로 현재 `TRANSLATION_FORMAT.md`, 실제 `LocaleDisplayRules` 및 원본 퀘스트 conditions로 검증한다.
- 상인 정보만 요청되면 아이템/퀘스트까지 임의로 재번역하지 않는다. Nickname/FirstName/FullName/Location/Description 등 실제 존재하는 필드를 확인한다.
- 사용자가 정한 표기를 우선한다. 예: Saria → 사리아, Kolya → 콜리야. 상인 ID를 추측하지 않는다.
- 상인 소개는 자연스러운 존칭 설명체, 직접 대사는 해당 인물의 말투를 사용한다. 두 경우 모두 원문 문장이나 상인 영어 이름을 자동 병기하지 않는다.

### 4-2. 세력 고유명 확정 표기

**2026-10-12 사용자 정정:** BEAR/USEC/RUAF/UNTAR는 번역하지 않고 영문 그대로 표기한다. 기타 세력은 아래 지정 표기를 유지한다. 부모 데이터가 이미 아래 표기를 사용한다거나 기존 번역 JSON에 모두 반영됐다는 뜻은 아니다.

| 원문 세력명 | 번역 본문 표기 |
|---|---|
| BEAR | BEAR |
| USEC | USEC |
| Scav / Scavs | 스캐브 |
| RUAF | RUAF |
| UNTAR | UNTAR |
| Black Division / Black Div. | 블랙 디비전 |
| REMNANT — 세력의 고유명일 때 | 렘넌트 |

- 아이템명/단축명/설명, 퀘스트, 대사, UI에 공통 적용한다. BEAR/USEC/RUAF/UNTAR는 **대문자 영문 유지**이며, 스캐브 등 별도 지정한 명칭에만 해당 음차를 적용한다. 총기 모델명·탄종·FMJ 같은 기술 약어는 기존 규칙을 유지한다.
- 사용자 확정 표기를 우선한다. 새 세력의 발음이 불명확하면 근거를 확인한다. 세력명 RUAF/UNTAR를 임의로 러시아군/유엔군으로 풀어 쓰지 않는다. 일반 명사 soldiers/peacekeepers/remnants와 계급·병과·보스 등의 역할은 문맥에 맞게 번역한다.
- key/source/enum/bot role/파일명은 보존한다. 예: key=`ScavRole/RUAF`, source=`RUAF`, translation=`RUAF`.
- `베어(BEAR)` 같은 수동 원문 병기를 만들지 않는다. BEAR 자체를 영문으로 유지하며, 코드가 붙이는 원문 이름과 `mod_name` 출처는 이 명칭 표기 대상이 아니다.
- 요청한 모드 범위의 기존 번역도 대조한다. 이 지침 추가만으로 모든 기존 번역이 수정되었다고 보고하지 않는다.

## 5. 저장 형식과 적용 경로

일반 아이템은 원본에 있는 Name/ShortName/Description을 같은 ID별로 정리하되, 모든 데이터가 반드시 3행 세트라고 가정하지 않는다. 없는 필드를 만들어 넣지 않는다.

애드온 JSON 예시(아래 ID는 설명용이며 실제 작업에서는 원본 ID를 쓴다):

```json
{
  "schema_version": 1,
  "target_spt": "4.1.6",
  "mod_id": "example.mod",
  "mod_name": "Example Mod",
  "channels": {
    "locale": [
      {
        "key": "example_item Name",
        "source": "Example rifle",
        "translation": "예시 소총",
        "match_mode": "item_decorated"
      },
      {
        "key": "example_item ShortName",
        "source": "Example",
        "translation": "예시"
      },
      {
        "key": "example_item Description",
        "source": "A rifle.",
        "translation": "소총입니다."
      }
    ]
  }
}
```

- 위 본문만 저장하면 설명은 두 언어에서 `[Example rifle]\n소총입니다.\n(Example Mod)`로 표시된다. 이 표시 결과를 다시 translation에 넣지 않는다.
- 원시 `en_partX.json`의 번역만 요청되면 입력과 같은 키/구조로 한국어 값만 반환한다. 애드온 적용 요청이면 기존 해당 프로필에 source/translation 행을 추가한다. 서로 다른 저장 형식을 혼합하지 않는다.
- locale의 match_mode는 앞 행에서 상속되므로 첫 행과 전환 지점에 명시한다. display_type은 행마다 적용되며 상속되지 않는다.
- 일반 상인·퀘스트 메시지·UI는 default이다. 1.7.16부터 실제 퀘스트 설명은 quest_description, 업적 설명은 achievement_description으로 명시한다. 두 한국어 설정에서 코드가 본문 뒤에 줄바꿈+(mod_name)을 붙이며, 본문에 수동으로 쓰지 않는다. 목표·대사·완료 메시지에는 모드 출처를 붙이지 않는다. 업적 이름은 achievement_title로 지정하여 한영병기 설정에서만 같은 줄에 괄호 원문을 표시한다. 소문자 의류·bare ID·대문자 업적은 소스 정의로 확인해 명시한다. 이름과 설명 키가 다르면 name_key로 연결한다.
- 같은 모드의 locale·small_ui·notifications 등은 translations의 기존 모드 JSON 하나 안에 채널별로 추가한다. Small UI/UI Alerts 등 용도별 파일을 새로 만들지 않는다. config-ui와 native-locales는 서로 다른 로더 규격이므로 합치지 않는다. 현재 파일명과 profile ID는 **실제 translations JSON에서 확인한다.** 과거 통합 목록 `MERGED_TRANSLATIONS_1.7.16.md`(현재 미동봉·현행 JSON으로 대체 확인)는 현재 제공되지 않는다.
- F12 일반 설정은 config-ui의 GUID/section/key에 대응하는 translation_display_name/translation_description/categories/values를 수정한다. 실제 저장 키나 enum 값은 번역하지 않는다.
- C#에 직접 적힌 화면 문구는 기존 small_ui 등 채널과 연결 훅을 확인한다. 지원되는 지점이면 JSON만 수정한다. 미지원이면 정확한 메서드를 확인하여 기존 훅을 최소 확장하고 근거를 기록한다.
- 알림·메일은 해당 모드/상인 범위와 호출 경로를 확인한다. 원문이 다르면 억지로 적용하지 않는다.
- `{0}`, `{count}`, 태그, 이스케이프, 내부 식별자를 보존한다. 설정·게임 로직·파일 경로·숫자·boolean은 번역하지 않는다.

모드 전체 번역에서는 아이템뿐 아니라 퀘스트의 모든 실제 메시지/목표 키, 상인 정보, 세력·역할 표시명, 업적, 읽을 수 있는 문서·쪽지, 택시 대사·목적지, 직접 우편, F12와 전용 UI도 조사한다. 사용자가 정한 범위를 넘겨 재번역하지 않는다. 각 문자열의 **원본 파일/키 또는 메서드 → 표시 화면/화자 → 기존 채널 → 코드 변경 필요성**을 기록한다.

- 일반 클라이언트/NPC 동적 텍스트는 기존 exact/template/segment/segment_template/regex_segment 중 생성 방식에 맞춘다. .NET 정규식과 치환 변수를 보존하며 exclusive_group으로 발신 모드·화자 제한을 대신하지 않는다. locale의 exact/item_decorated는 별도 규칙이다.
- NPC 직접 우편은 `npc_messages`와 정확한 trader_id, USER/SYSTEM 우편은 `server_messages`의 exact/segment를 사용한다. TemplateId 우편은 locale 경로를 확인한다. 이미 저장된 우편이 언어 전환만으로 재번역된다고 주장하지 않는다.
- 알림/오류는 `DisplayHooks.ProfileByPluginGuid`의 연결을 확인한다. 현재 dialogs는 Vagabond, server_errors는 Vagabond/Croupier 전용이다. 새 프로필에 같은 채널명을 쓰는 것만으로 다른 모드에 적용되지 않는다.
- 일반 F12 config-ui, CustomDrawer 전용 처리, small_ui의 지정 메서드, Dynamic Maps 전용 UI/버전 검사, Weapon Camo의 리터럴/캐시, PitFireTeam 자체 로케일은 서로 다른 경로다. 세부 연결과 제한은 안내서 2·4·5절을 따른다.
- `locale_source_fallback`은 병합된 로케일의 정확한 영문 원문 일치와 부모 번역 보호 조건을 유지한다. `locale_clone_suffix`는 실제 부모 키와 생성된 접미부를 확인한다. `reference_only`를 적용 완료로 세지 않는다.
- 새 모드라는 이유만으로 새 C#을 만들지 않는다. 기존 연결이 없으면 실제 호출 지점을 확인해 필요한 범위만 확장한다. 로그·내부 경로·로직 문자열을 화면 번역 대상으로 취급하지 않는다.

## 6. 검증과 결과 보고

- JSON 문법/중복 속성, 키/source 보존, 중복 프로필, 치환 변수, 누락된 실제 표시 필드를 확인한다.
- `build/validate_translations.py`를 실행한다. F12는 별도로 GUID/section/key/values를 검증한다.
- 등록된 행의 검사만으로 끝내지 않는다. 실제 서버 locale과 원본 모드 정의에서 번역 데이터로 역대조하여 없는 행도 찾는다. `docs/tools/audit_runtime_coverage.py`와 실제 raw locale 재현 테스트를 사용하고, 원문 변경은 대상·수량·장소·레이드 발견 조건까지 검토한다. 적용 실패를 숨기려고 source 일치 검사를 제거하지 않는다.
- 기존 번역 본문에 수동 생성된 전체 원문/모드명이 있으면 동일 문자열인지 확인해 해당 부분만 정리한다. 의미가 있는 괄호를 일괄 삭제하지 않는다.
- 코드 변경 시 실제 부모 표시값, 한국어/한영병기/영어 전환, 원문 불일치, 중복 괄호, 가격·탄약 장식을 검증한다.
- 요청 범위를 넘어 DLL·부모·설치본·빌드 방식을 바꾸지 않는다. 데이터 추가만으로 되는 작업은 코드 재작성 없이 끝낸다.
- 결과에는 기준 모드/버전과 원본 경로, 변경 파일과 채널, 추가/변경 개수, 코드 수정 이유(있을 때), 검증 결과와 실제 산출물, 인게임 미확인 여부를 남긴다.
