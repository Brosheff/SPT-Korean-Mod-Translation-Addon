### 발견된 실제 결함과 근본 원인

**Aishi 퀘스트 조건의 표시 유형 미등록.** 애드온의 `LocaleDisplayRules.Resolve()`는 공백 없는 독립 ID를 `quest_objective`로 자동 분류하지 않고 `default`로 처리한다. 그런데 Aishi `db/**/Quests/quest_definitions.json` 내 `conditions.AvailableForFinish`의 실제 조건 `id`와 일치하는 번역 행 총 **455개** 가운데, 신버전 업데이트 직후에는 **전부** `display_type: "quest_objective"`가 없었다. JSON 번역 자체가 존재해도 한국어와 영어 원문을 목표 항목에 병기하는 표시 규칙이 적용되지 않는 문제다.

- 최초 확인한 신규 목표 3건(`32333f92e15faf8e8920d928`, `71db1f0df25f9bde7957c7a7`, `f3ea573061656070b2292e20`)을 수정함.
- 같은 원인으로 기존 452건에도 누락이 있음을 실제 조건 정의에서 재확인했고, 조건 ID 455건 **모두** `display_type: "quest_objective"`를 명시함. 별도 추측성 bare ID에는 이 유형을 부여하지 않음.
- 확인된 조건 종류: `CounterCreator` 161, `HandoverItem` 103, `Skill` 65, `FindItem` 40, `Quest` 32, `WeaponAssembly` 21, `LeaveItemAtLocation` 19, `PlaceBeacon` 8, `TraderLoyalty` 5, `Kills` 1, `SellItemToTrader` 1. 동일 ID가 일부 정의에 중복될 수 있으므로 건수는 **고유 번역 ID** 기준.

**Aishi 장비 설명 6건의 어색한 한국어 표현.** 신버전에서 바뀐 장비 영문 설명을 따라 "화이트 터스크 에디션 버전입니다", "화이트 터스크 경량형 버전입니다"로 적힌 부분을 각각 "화이트 터스크 에디션입니다", "화이트 터스크 경량형입니다"로 교정했다. 영문 `source`와 키는 건드리지 않았다.

### 의심 항목을 코드 확인 후 오류에서 제외한 사례

- `c3dd45d0da2679c60db3c3cb description`(Fast Travel)은 처음에 표시 유형 누락이 의심되었지만, 실제 프로필에 **이미** `display_type: "quest_description"`이 있으므로 오류가 아니다. 이 행은 바꾸지 않았다.
