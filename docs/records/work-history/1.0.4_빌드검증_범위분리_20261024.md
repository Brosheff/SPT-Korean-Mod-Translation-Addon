# 1.0.4 빌드 검사 범위 분리 (2026-10-24)

- 원인: `verify_workflow.py source`가 `docs_purity_checks()`를 호출하고, 검사 함수가 `root.rglob('*')`로 저장소 전체를 검사하여 `Upload/`의 과거 소스·라이선스·README를 GPT 작업 자료 위치 위반으로 오판함.
- 변경: `source`에서 GPT 자료 검사를 분리. `documents`에서도 파일 확장자별 전체 프로젝트 재귀 검사를 폐지하고, 현재 `docs`와 명시된 루트 GPT 전용 폴더만 검사.
- 보존: 번역 JSON, F12, C# 소스, 배포 ZIP 정합성 검사 유지. `Upload/`의 과거 자료를 삭제·이동하지 않음.
- 검증 결과 (실행): `verify_workflow.py source`, `documents`, `validate_translations.py`, `verify_quartermaster_contracts.py`, `build_supported_mods.py` 통과.
- 회귀 시험: `Upload/` 아래 예전 README·라이선스·Python·CSV 등 79개 임시 파일에서 `source`/`documents` 모두 통과. F12 GUID를 잘못 넣으면 `source` 실패. `docs/` 임시 기록과 루트 `tools/`은 `documents`만 실패하며 `source`는 통과. 임시 시험 파일은 삭제함.
- 배포 검사: 임시 스테이징/ZIP에 현재 JSON과 모의 PE 헤더 DLL을 배치해 `distribution` 통과. 임의 README를 스테이징에 넣었을 때 오류 3건 검출. 모의 PE 헤더는 실제 컴파일 DLL이 아니므로 **컴파일/실행 검증으로 간주하지 않음**.
- 제한: 이 환경에는 Windows CMD/PowerShell 및 `dotnet` SDK가 없어 Windows CMD 실행·실제 C# 빌드·게임 실행은 실시하지 못함.
