# 1.0.4 번역 회귀 전면 재감사 — 코드 경로 및 실제 판정

## 범위와 기준

- 기준 원본: 사용자가 제공한 `SPT-Korean-Mod-Translation-Addon 1.0.3.zip`.
- 검토본: 마지막 1.0.4 회귀 복구 소스에서 독립 작업 복사본을 만든 후 검증.
- 현재 모드 원본: `ISB-Aishi-v.2.0.4.zip`, `ISB-Special-Forces-2.0.1.zip`, `SPT-COTI-3.4.1.zip`.
- `docs/patches`는 사용자 요청에 따라 **읽거나 변경하지 않았다**.
- 애드온의 다른 지원 모드 원본은 제공되지 않았다. 다른 모드에 대한 검사는 1.0.3 ↔ 1.0.4 번역 프로필·F12·공통 소스 회귀 **정적 검사**에 한정한다.

## 화면에 드러난 아이시 상인 소개 오류 — 코드 근거

1. Aishi 2.0.4 `aishi_trader.cs`의 `AishiTraderRegistration.OnLoadAsync`에서 `aishiLogger.AddTraderToLocales`에 **구형 영어 소개**를 직접 전달한다.
2. `AishiLogger.AddTraderToLocales`는 전 언어의 서버 로케일에 `FullName`, `FirstName`, `Nickname`, `Location`, `Description`을 추가하는 transformer를 등록한다. `db/base.json`에는 `name: Juna Aishi`, `nickname: Aishi`가 있다.
3. `AishiLocaleFinalization.OnLoadAsync`는 이후 `AishiLocaleData.Apply`를 등록한다. `Apply`의 기본 영어 fallback은 이미 정상 텍스트가 존재하는 키를 덮어쓰지 않으며, `kr.json`은 제공된 모드에 존재하지 않는다. 반면 `db/CustomLocales/en.json`에는 변경된 소개 문구와 `FullName: Aishi`, `FirstName: Juna Aishi`가 있다. **영어 en.json 원문이 한국어 서버에서 항상 최종 원문이라고 가정할 수 없다.**
4. 직전 1.0.4 `translations/ISB Aishi.json`은 `en.json`을 기준으로 3개 키의 원문을 등록했다. 이 경우 구형 텍스트가 주입되는 한국어 서버에서 기본 프로필의 exact 매칭이 실패한다. 직전 회귀 복구본에는 별도 호환 프로필이 있으나, 본 파일 없이 기본 JSON만 덮어쓴 설치에서는 이 세 키가 누락될 수 있다.
5. 이번에는 3개 키의 **기본 프로필** `source`를 Aishi 상인 등록 코드의 한국어 서버 주입값에 맞춰 되돌렸다. 기존 `en.json`의 변경된 원문 및 그에 맞는 한국어는 **이미 존재하는 보조 프로필에 유지**했다. 나머지 번역이나 C# 런타임은 수정하지 않았다.
6. 사용자 스크린샷은 이전 영어 소개가 실제로 표시됐다는 증거다. 정확히 어떤 ZIP의 9개 파일이 사용자 게임에 설치되었는지 또는 서버 transformer의 최종 처리 순서는 실행 로그 없이 확정할 수 없다. 따라서 실게임 해결 여부는 **미확인**이다.

## 프로젝트 전반 교차검사

- 원본 1.0.3의 `translations` 전체 활성 **키·원문 행 20,418건**, 현행 파일들에 **누락 0건**. 동일 `(채널, 키, 원문)`에 서로 다른 번역이 매칭되는 **확정 충돌 0건**. 한국어 변경 12건은 앞선 Aishi 화자별 수정 기록을 참고하여 유지하되, 의미 개선 여부는 별도 감수 대상으로 남긴다. 이 수치는 **데이터 후보 보존**이지 게임 적용 성공 건수가 아니다.
- 현재 검토 소스 프로필 **115개**(1.0.3 기본 113개와 호환용 2개). C# 로더는 `src/EditableProfiles.cs`에서 파일명을 정렬하여 파일을 읽고, `src/ClientLocaleModOverlay.cs`에서는 키가 동일해도 원문이 다른 후보를 따로 순회한다.
- Aishi 신버전 `db/**/en.json` 문자열 1,131건: 등록된 정확 원문 후보 1,131건, 등록 누락 0건. 별도로 `db/CustomItems`의 영어 이름·단축명·설명 **3,061필드** 중 일치 후보 905건, 미등록 2,156건. 미등록이 실제 화면에 표시되는지는 각 아이템 등록/부모 로케일과 게임 스냅샷으로 확인해야 한다.
- Special Forces 신버전 서버 `Server/db/**/Locales/en.json` 및 `CustomLocales/en.json`의 실제 문자열 587개: exact 일치 후보 28건, 미등록 559건. 별도 자막 JSON `entries` 222개 중 애드온 `small_ui`에 영어 문자열과 정확히 일치하는 후보는 21건, 나머지 201건은 훅/번역 미등록 여부를 추가 검토해야 한다. `small_ui`의 segment/regex 규칙 적용 가능성은 단순 리터럴 수치에 포함하지 않았다.
- COTI 3.4.1 `Coti.Client/CotiF12Config.cs`에서 리터럴 section/key를 쓰는 `_file.Bind` 선언 29종은 `com.lennoxp90.coti.json`에 전부 존재한다. 다른 설정 생성 경로·조건부 빌드·동적 UI까지 모두 검증한 것은 아니다.
- 일반 번역 스키마, 서버/클라이언트 정적 코드·F12 검사, Quartermaster 계약 검사, docs 구조 검사, 신규/기존 원문 호환 검사와 전수 대조 도구를 실행했다. 각 검사 이름과 출력은 별도 검사 증거 ZIP의 요약 파일을 확인한다.

## 실패 원인과 수정 원칙

- **직접 확인된 원인:** Aishi가 같은 로케일 키에 대해 `AddTraderToLocales`와 `en.json`이라는 서로 다른 값 공급 경로를 사용하고, 기존 애드온 기본 프로필이 언어별 선행 transformer의 값을 고려하지 않은 점.
- **이번 수정:** 아이시 상인 원문 3건의 기본·보조 프로필 우선 배치와 호환 검사 강화. `translations` 이외의 런타임 코드·원본 모드는 수정하지 않았다.
- **동일 원인 확대 검사:** 원본 1.0.3 전체 번역 후보 보존, 동일 source 충돌, 세 신버전 모드의 실제 `en.json` 공급 경로, 아이템·자막 별도 공급 경로, F12 설정을 별도로 집계했다.
- **수정 미실시 범위:** Aishi 아이템 미등록 2,156필드와 SF 로케일 559개·자막 201개는 개별 사용자 출력 위치 및 신뢰할 수 있는 한국어 번역이 확인되지 않았으므로 검증 없이 자동 생성·덮어쓰지 않았다. 완역 또는 미번역 0건이라 보고하지 않는다.

## 남은 검증

- 실제 사용자 설치 시점의 전체 `BepInEx/plugins/SPT_Mod_Korean_Addon/translations` 목록과 한국어 서버 raw locale snapshot을 확보하지 못했다. 인게임 결과는 미확인.
- 현재 실행 환경에서 .NET SDK와 SPT 게임 런타임이 없어 클라이언트·서버 새 DLL **컴파일 미실시**, 인게임 표시 테스트 **미실시**.
- 1.0.4 소스 ZIP은 컴파일 가능한 원본 소스 구성일 뿐 설치용 정식 빌드 ZIP이 아니다. 데이터 ZIP은 사용자가 정상 설치된 기존 DLL을 가지고 있는 경우에만 덮어쓰는 번역 패치다.
- 정식 완료를 선언하려면 먼저 오류 재현 당시의 언어별 실제 서버 원문과 로더에서 선택된 후보를 대조하고, 새 DLL 빌드 후 신규 설치·1.0.3 덮어쓰기 설치 양쪽에서 한국어·한영병기·F12·퀘스트·아이템·상인 UI를 게임으로 확인해야 한다.
