# 1.0.4 문서·작업기록 분리 결과 (2026-10-24)

이 파일은 작업 기록이므로 **`docs/`가 아닌 `records/work-history/`**에 보관합니다.

## 문제와 원인

- `docs/`에 작업 인계·회귀 복구·감사 CSV·버전 관리 대장과 과거 `patches` 기록이 혼재되어 매뉴얼과 기록의 구분이 없었습니다.
- `tools/verify_workflow.py`가 이력 문서를 `HISTORICAL_DOCS`로 필수화해, 기록을 `docs/` 밖으로 이동하면 검사 실패하는 구조였습니다.
- 기존 소스에 ZIP을 단순 덮어쓰면 과거 기록 파일이 삭제되지 않았습니다.

## 구조 변경

- `docs/`에는 7개의 현재 매뉴얼/작업 양식과 1개 번역 프롬프트만 남겼습니다(8개).
- `docs/`에서 작업·감사·버전 자료 43개를 `records/work-history`, `records/audits`, `records/versioning`, `records/patches`로 내용 변경 없이 이동했습니다. 이 중 기존 `docs/patches` 기록 31개는 본문을 읽거나 변경하지 않고 옮겼습니다.
- `docs/prompts/vanilla_trader_dialogue_reference.json`은 매뉴얼이 아니라 참고 데이터이므로 `reference-data/`로 이동했습니다. 원본 바이트를 유지했습니다.
- 최상위 `AGENTS.md`는 단일 문서 인덱스와 저장 규칙 중심으로 축약했습니다. 전문 절차는 기존 전용 매뉴얼에 남겼습니다.
- 매뉴얼 내부의 기록 경로와 과거 감사 참조를 새 위치에 맞춰 변경했습니다. 과거 감사는 현행 지침이 아니라 선택적 참고 자료입니다.
- `tools/verify_workflow.py`의 `documents` 및 `source` 검사에 `docs` 내 비매뉴얼 파일·디렉터리 금지 검사를 추가했습니다. `HISTORICAL_DOCS` 필수화 검사는 제거했습니다.
- `tools/migrate_docs_records.py`를 추가했습니다. 기존 소스에 덮어쓰면 남는 이전 `docs/` 기록을 `records/`로 이관하고, 보관본과 동일한 경우 `docs/`의 중복 원본만 제거하며, 내용이 다르면 별도 기록으로 보존합니다.

## 실행한 검사

- `python tools/verify_workflow.py documents` — 통과
- `python tools/verify_workflow.py source` — 통과
- `python tools/validate_translations.py` — 113개 프로필 통과
- `python tools/verify_quartermaster_contracts.py` — 계약 정적 검증 통과
- 오류 주입 시험: `docs/`에 기록 Markdown·감사 CSV·`patches` 디렉터리 삽입 시 `documents`와 `source` 모두 실패함을 확인
- 기존 파일 이관 재현: 동일 기록 중복 제거·미등록 보고서 이관·매뉴얼 보존 모두 확인
- 원본 ZIP의 이동된 44개 파일(참고 JSON 포함)을 SHA-256으로 대조해 내용 변경 0건 확인
- 번역 JSON, F12 JSON, C# 실행 소스, `note`, 원본 자료는 변경하지 않음

## 확인하지 못한 사항

DLL 컴파일 및 실제 SPT 실행은 수행하지 않았습니다. 작업은 문서 구조·관련 검사 도구 수정에 한정됩니다. 자동 검사만으로 앞으로 모든 작업자가 지침을 실제 읽고 따르는 것까지 보증할 수는 없습니다.

## 덮어쓰기 기존 소스 정리

기존 프로젝트 위에 새 소스 ZIP을 덮어쓰면 오래된 `docs/` 기록이 남을 수 있습니다. 해당 프로젝트 루트에서 다음을 실행하십시오.

```text
python tools/migrate_docs_records.py
python tools/verify_workflow.py documents
```
