# 1.0.4 Manimal Terminal 컴파일 차단 및 관련 코드 전수 검사 (2026-10-24)

## 사용자 재현 로그
- `src/ManimalTerminalUiHooks.cs(121,57) error CS0246: EFT 형식 또는 네임스페이스 없음`.
- 사용자 환경의 `net48` 클라이언트 컴파일이 실제 실패했으므로 기존 정적 검사의 빌드 정상 판정은 적용할 수 없다.

## 원인과 원본 대조
- `SPT_Mod_Korean_Addon.csproj`는 `references/client/`의 10개 어셈블리만 참조하며 EFT의 `Assembly-CSharp.dll`을 참조하지 않는다. 이 설계는 직접 게임 설치 DLL 의존성을 피하기 위한 것이다.
- 원래 추가한 `AfterInteractionActions(ref EFT.UI.AvailableInteractionState __0)` 선언만 클라이언트 소스에서 직접 `EFT.*` 타입을 요구한다.
- 제공 원본 `MOD SOUCES.zip` 안 `ManimalTerminal-master.zip`, `terminal-client/TerminalPumpStation.cs` 및 `TerminalGatesExplosion.cs`의 Harmony `Postfix` 두 메서드는 실제로 `ref EFT.UI.AvailableInteractionState __result, GamePlayerOwner owner, EFT.Interactive.Switch interactiveSwitch`라는 인자 3개를 받는다. 그 값은 원본 모드 내부 타입이며 클라이언트 번역 DLL의 직접 참조로 사용하면 CS0246이 발생한다.
- 이 두 Postfix는 `Terminal` 씬 소속 스위치에서 `AvailableInteractionState.Actions`의 이름을 구성한다. 번역 대상은 이 스위치 메뉴 문구뿐이다.

## 변경 내용
1. `src/ManimalTerminalUiHooks.cs`: 원본 `ref EFT.UI.AvailableInteractionState` 매개변수를 제거하고 Harmony가 제공하는 `object[] __args`의 첫 인자로 상태를 받아 `Actions`와 `Name`을 리플렉션으로 조회한다. `__args[2]`가 `Terminal` 씬의 `UnityEngine.Component`인 경우에만 변경하며, 행동 `Action`, `Disabled` 및 이벤트 흐름은 변경하지 않는다. 이름만 기존 `small_ui` 프로필로 치환한다. 기존 10개 대상과 메서드 해석 정책은 유지한다.
2. `build/check_csharp_delimiters.py`: 실제 C# 코드(주석·문자열 제외)에서 `EFT.*` 직접 타입 참조가 나타나면 빌드 전에 실패시키는 사전 검사 추가. `build/verify_release.py source`의 기존 호출 관계를 활용하며 GPT `docs/`와 빌드를 연결하지 않는다.
3. `docs/tools/test_build_independence.py`: 동일한 잘못된 타입 선언을 임시 프로젝트에 추가하면 `source` 검사가 실패하는 부정 회귀 시험 추가.
4. `docs/tools/VERIFY_WORKFLOW.md`: 정적 검사 범위와 실제 컴파일의 구분 문구 갱신.

## 검증 불가와 남은 범위
- 현재 실행 환경에 .NET SDK, Windows CMD/PowerShell, 실제 SPT 게임이 없어 **실제 `dotnet build`·DLL 실행·Harmony 런타임 동작·인게임 번역을 검사하지 못했다**.
- 이 보고서의 '정적 검사 통과'는 Windows 컴파일 성공 보장이 아니다. 게임에서 얻은 추가 오류는 전체 클라이언트·서버 범위를 재조사해야 한다.
- JSON, F12 번역, 다른 모드 C# 로직, 빌드 스크립트, 공개 `note` 내용은 변경하지 않았다.
