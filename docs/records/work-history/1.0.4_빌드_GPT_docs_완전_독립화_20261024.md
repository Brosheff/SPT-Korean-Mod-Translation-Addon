# 1.0.4 빌드·GPT docs 독립화 작업 기록

## 원인
- `BUILD_DISTRIBUTION.ps1`이 `docs/tools`에 있는 검사기, 지원 목록 생성기, NuGet 설정을 필수로 참조해 `docs` 누락 또는 문서 이동 시 컴파일 전에 실패했습니다.
- 단일 `verify_workflow.py`가 빌드 입력·배포 검증과 GPT 문서·인계 검사를 혼합하여 검사 범위 관리가 복잡했습니다.
- 이전 ZIP을 기존 폴더에 덮어쓸 때 오래된 빌드 파일은 `docs/tools/`에 남을 수 있었습니다.

## 변경
1. 빌드 전용 Python 도구 6개를 `build/`로 이동(라이브러리 포함). `build/verify_release.py`가 실제 소스·F12·배포 ZIP만 검사합니다.
2. `docs/tools/verify_workflow.py`에는 GPT 문서·작업 인계 검사만 남겼으며, 빌드에서 호출하지 않습니다.
3. `NuGet.Offline.Config`의 경로 의존을 없앴습니다. 빌드에서 오프라인 NuGet 설정 XML을 시스템 임시 폴더에 생성해 사용 후 삭제합니다.
4. `BUILD_DISTRIBUTION.ps1`의 빌드 검사·지원 목록 생성·계약 검사 경로를 모두 `build/`로 수정했습니다. 상대 참조 DLL 경로를 프로젝트 루트 기준으로 계산하도록 보강했습니다.
5. 기존 설치 폴더에 남은 구형 `docs/tools` 빌드 도구는 별도 이관 명령으로만 `docs/records/legacy-imports/old-build-tools/`에 보존합니다. 빌드는 이관을 요구하거나 수행하지 않습니다.
6. 현재 매뉴얼의 경로와 역할 정의를 갱신하고, `docs/tools/test_build_independence.py`에 독립성·회귀 검사를 추가했습니다.

- `docs` 없는 복사본의 번역·계약·목록 생성 검사: 통과
- 손상된 실제 F12 GUID와 번역 `mod_id`: 검출

## 검증 한계
- 작업 환경에 `powershell.exe`/`pwsh` 및 `dotnet` SDK가 없어 **실제 Windows CMD 실행, NuGet restore, C# 컴파일 및 게임 구동은 미실시**했습니다.
- DLL이 아닌 테스트용 PE 헤더는 배포 검증기를 시험하기 위한 것일 뿐 실제 설치 패키지로 전달하지 않습니다.
- 실제 운영 환경에서 net48/.NET 10 SDK 참조 어셈블리 의존성은 이 환경에서 확인할 수 없습니다.

## 변경 범위
- C#·번역 JSON·F12 JSON·기존 `mod_version`·`note`의 기존 내용은 수정하지 않았습니다.
- 최상위 `Upload/`에 보관된 과거 소스는 빌드 및 GPT 자료 검사 범위 밖입니다.
