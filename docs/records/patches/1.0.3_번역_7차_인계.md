# 1.0.3 번역 작업 인계 — 7차 (2026-10-16)

> **1.0.3 개발 중간 소스**입니다. 실제 프로젝트 버전은 1.0.2를 유지합니다. 이번 회차의 `Under Fire` 번역문·한정 훅은 **소스 작성/정적 검사 단계까지만** 확인했습니다. SPT 4.1.6 C# 컴파일, 설치 ZIP, 게임 내 표시 테스트는 수행하지 않았습니다.

## A. 기준·작업 범위·문서

- 누적 기준: `SPT-Korean-Addon-1.0.3-Development-Batch6-Source.zip`과 `SPT-Korean-Addon-1.0.3-Batch6-Inventory-Handoff.zip`. 기존 1~6차 번역·훅/후처리 유지.
- 직접 대조 원본: `UnderFire-1.0.0.zip` (`UnderFire-1.0.0/Plugin.cs`, `Adrenaline.cs`), `ISB-Aishi-2.0.3.zip`, `ISB-Special-Forces-2.0.0.zip`.
- 사용자 범위: Under Fire의 `Adrenaline` 효과 표시명, ISB Aishi와 ISB Special Forces가 연결된 독립 결과 화면, 기존 bare ID 두 개의 목표 연결. 이 외 번역과 모드 원본은 변경하지 않음.
- `docs/모드번역_작업절차.md` → `번역작업안내서.md` → `TRANSLATION_FORMAT.md` → `prompts/translate_prompt.txt` → 인계 양식 → `tools/VERIFY_WORKFLOW.md`의 규칙을 다시 확인. 원본 UI 출력/조회, `source`, 로더·훅 경로를 분리하여 판정.

## C. 후보 역대조·단계별 검증

- 인계 ZIP의 `candidate_inventory.json`, `handoff.json`: 6차 550개에서 7차 552개로 갱신. **번역·코드 작성 369, 원문 유지 93, 비대상 87, 보류 3**. 그중 Under Fire 1개는 보류 → 번역·훅 소스 작성으로 이동. 새로운 섹션 키 보류 1개, Aishi 로케일 조회 비대상 1개 추가.
- 보류 3개: `sf:raidresult:independent`, `sf:raidresult:standing-section-key`, `aishi:bare:refs`. 언어/플러그인 초기화 순서 미검증은 별도로 조건부 완료 상태에 기재.
- 후처리: `tools/build_supported_mods.py`의 Under Fire F12 별칭을 신규 `mod_id`와 일치시켜 같은 모드의 UI와 F12가 한 행으로 결합되도록 변경. `note/번역지원모드목록.md` 재생성 결과 **총 164개 유지, 게임 내 텍스트/UI 111개, F12 전용 53개**. 번역 프로필 1개 신규; 기존 JSON 내용은 보존.
- 검사: `tools/verify_workflow.py source`, `tools/verify_workflow.py documents`, `tools/validate_translations.py`, `tools/verify_workflow.py handoff`, `python -m unittest discover -s tests/WorkflowChecks` 각각 기록된 통과 결과. Under Fire 한정 훅 계약 검증 테스트를 1개 추가하여 현재 회귀 **31개**.
- 실행 단계: JSON/키/정적 연결 검사 **통과**; C# 빌드 **미실시** (`dotnet` SDK 미확인); 배포 ZIP **미제작**; 인게임/언어 전환/작동 시점 **미확인**. 정적 테스트는 로더 실행이나 IL 패치 실행을 보증하지 않음.

## E. 다음 회차 우선순위

1. SPT 4.1.6 참조 환경에서 실제 `EFTEffectManager` 효과 표시 수명주기와 Under Fire의 `Awake` 순서를 검증하여, 훅 시점이 늦으면 미적용 상태를 해결할 수 있는 **모드 한정** 경로를 찾습니다. 범용 EFT 건강 화면 후킹을 임의 승인하지 않습니다.
2. ISB Special Forces 레이드 결과 UI가 한국어 레이드 종료 화면에서 해당 로케일 키를 조회/표시하는지 확인하고, `isb_aishi_standing_section`의 실제 영어 원문 및 한국어 제목 인식 경로를 확인합니다.
3. Aishi 두 bare ID는 실제 퀘스트 조건/조회 경로 증거가 확보될 때만 `quest_objective`를 지정합니다.
4. 한정된 C# 빌드 → 배포 구조 확인 → 실제 SPT 게임 표시 검증을 각 단계로 구분합니다.
