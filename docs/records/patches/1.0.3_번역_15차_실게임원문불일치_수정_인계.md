# 1.0.3 개발 인계 — 15차 VKS 아이템 실제 표시 원문 차이 수정

## 근거와 기존 결함

- 이전 회차에서 **원본 모드 ZIP 영어와 번역 JSON source의 일치**만 검사해 놓고 실제 인게임 표시를 검증했다고 혼동했다. 그 결과 영어 이름/설명이 게임에서 남았음.
- 사용자 스크린샷: 프리셋의 VKS 12.7x55 ST-130 **총구제퇴기** 상세 패널에 `VKS 12.7x55 ST-130 muzzle brake` 및 `Muzzle brake for the VKS 12.7x55 ST-130 rifle. Reduces recoil and muzzle rise.` 표시. 본체 이름은 한국어가 표시돼 **전체 번역 로더 중단이 아니라 일부 키의 실패**가 관찰됨.
- 업로드된 원본 `Russian-SF-Pack-2.0.1.zip`의 `RussianSFPack/Resources/db/CustomItems/VSSK.json`은 해당 부품에 `VSK...`를 사용. `translations/Russian Special Forces Pack.json`도 그 원문을 정확히 복사함. 하지만 실제 게임에서는 `VKS...`로 보였음.
- 원본 아이템 ID `6ab051dcb07a9b85e5577d0c`를 통해 해당 `Name`/`Description` 키를 식별함. **사용자 스크린샷에 템플릿 키 자체는 보이지 않으므로**, 실제 서버 로케일 키 매칭 확인은 별도 검증 사항임.
- `src/ClientLocaleModOverlay.cs`의 `Translate`는 일치한 source 또는 허용 장식만 번역하여, 위 사례에서는 영어가 남을 수 있음. 모든 영어 잔류가 같은 원인인지는 알 수 없음.

## 15차 소스·데이터 변경

| 경로 | 변경 | 이유 |
|---|---|---|
| `src/TextRules.cs` | locale 행에 `source_variants: List<string>` 필드 | 검증된 대체 원문 저장 |
| `src/ClientLocaleModOverlay.cs` | `source` + 검증된 변형만 정확히 일치하는 키에서 적용, 별칭 유효성 검사 | 유사도 기반 오적용 및 전체 로더 조건 해제 방지 |
| 위 로더 | 매칭된 실제 이름을 한영병기 및 설명의 원문 이름 머리말에 사용 | `[VSK...]` 대신 실제 `[VKS...]` 사용 |
| `translations/Russian Special Forces Pack.json` | ID `6ab051dcb07a9b85e5577d0c`의 Name/Description 2행에 정확한 `source_variants` 추가, 한국어 본문에는 VKS 사용 | 원본 ZIP의 VSK도, 실제 화면의 VKS도 허용 |
| `tools/validate_translations.py`, `tools/audit_runtime_coverage.py` | 변형 필드 검증·실제 로케일 스냅샷 비교에 반영 | 이전 검증 구멍 보완 |
| `tests/LocaleDisplayContract/Program.cs` | 원문 VSK/실게임 VKS, `kr`/`kr-en`/`en`, 설명 머리말, 미등록 변형, 유효하지 않은 별칭 등 계약 테스트 추가 | 빌드 가능한 환경에서 DLL 동작 검증 |
| `tests/WorkflowChecks/test_verified_item_locale_sources.py` | 별칭 범위·실행 스냅샷 검사 도구 회귀 테스트 추가 | 검증된 변형만 허용되는지 검사 |

**원본 모드의 영어 원문을 덮어쓰지 않았다.** 모드 원본 파일·DLL은 변경하지 않았고 다른 아이템명/부착물에는 추측한 `VKS` 변형을 넣지 않았다. DLL을 재빌드해야 하는 기능이며 단독 JSON 덮어쓰기로 해결되지 않음.

## 동형 후보 및 범위 재감사

- 원본 `RussianSFPack` 327개 `locales.en` 키·source와 15차 한국어 프로필 327행 source의 일치 상태는 **327/327**. 기존 일치 검사로는 실제 표시 차이를 검출할 수 없다는 것을 재확인함.
- 전체 111개 프로필의 locale 키를 대소문자 무시 방식으로 비교하면 **중복 후보 키 133개**, 이 중 서로 다른 원문 또는 번역을 가진 후보 **13개**(서로 다른 프로필 간 9개, 한 프로필 내부의 대소문자 별칭 4개)가 검토 대상으로 분류됨. **13개 전부가 실제 번역 오류라고 확정한 것이 아님.** 상세 기록: `1.0.3_15차_동일키_원문변형_감사.json`.
- 사용자 제공 스크린샷에서 원문을 검증한 두 필드만 현재 별칭을 등록함. 다른 1~13차 번역의 **실제 서버 원문 전체가 제공되지 않았으므로** 런타임 전수 일치/정상 적용은 미확인으로 유지함.
