# 1.0.3 ArenaMode 0.1.1 — 컴파일 실패 이후 독립 UI 훅 재구현 인계

## A. 재작업 이유 및 기준

- 재작업 기준: `SPT-Korean-Addon-1.0.3-ArenaMode-0.1.1-Independent-UI-Fix-Source.zip` (직전 누적 소스 전체)
- 원본 검토: `ArenaMode-0.1.1.zip`의 `ArenaMode.Client/Session` 7개 UI 클래스, `Hud` 3개 UI 클래스 및 기존 애드온 연결 경로
- 사용자 컴파일 증거: `src/SmallUiLiteralHooks.cs(574,95): error CS1026: )가 필요합니다.`
- 이전 제출물의 ArenaMode 독립 UI 훅 추가 구현을 폐기하고, 새 파일 `src/ArenaModeUiHooks.cs`에 출력 경계 훅을 재구현함.
- 실제 게임 모드·원본 DLL·서버 코드·아이템 키·프로필 `source`·F12 저장 키는 수정하지 않음.

## B. 재구현 상세

1. `src/SmallUiLiteralHooks.cs`: 구형 `PatchArenaRenderedText`, 렌더링용 캐시, TMP setter 리다이렉션 및 기타 ArenaMode 관련 확장 메서드들을 제거. 기존 공통 훅과의 연결은 `ArenaModeUiHooks.Enable/Patch/RefreshLanguage/Disable` 4개 진입점으로 제한.
2. `src/ArenaModeUiHooks.cs` **신규**: ArenaMode 0.1.1의 실제 독립 UI 클래스와 화면 문자열 출력 메서드만 지정. TMP의 `text` 출력 경계, `HoverTooltipArea.SetMessageText` 출력 경계, Arena 점수판의 `Label`·킬피드 `DeathCause`를 별도 적용. 게임 모드/변형 규칙의 식별 문자열을 변경하지 않음.
3. 범위 제한: `ArenaMode.Session.ArenaModeSelectionView`, `ArenaMutatorsView`, `ArenaAreaSelectionView`, `ArenaEquipmentChoiceView`, `ArenaDeathmatchRulesView`, `ArenaZombieRulesView`, `ArenaTdmMatchRulesView`, `ArenaMode.Hud.ScorePanel`, `ArenaPowerupPanel`의 검증된 메서드 이름만 포함. 외부 TMP/Unity 전체에 훅을 추가하지 않음.
4. 기존 소규모 직접 리터럴 표면인 `ArenaPanel`, `TacticalBuyPanel`, `ArenaSideSelectionLayout`은 기존 감사 훅을 유지. **중복 번역을 막기 위해 새 출력 훅이 담당하는 5개 클래스는 기존 리터럴 패치 대상에서 제거**함.
5. 툴팁은 기존 원본 메서드를 원래 `rawText` 값으로 호출. 예외를 조용히 삼켜 원본 표시 동작까지 생략하던 구현을 제거.
6. 언어 변경 캐시의 원문과 최종 출력값을 각각 보관. ArenaMode가 같은 TMP 라벨을 다른 경기/모드 문구로 재사용했을 때 이전 캐시가 새 문구를 덮어쓰지 않도록 비교함.
7. HUD의 점수/강화 효과의 숫자·색상 태그와 플레이어 이름은 보존하고, 영문 고정 부분에만 사전에 확인된 번역을 적용함.
8. `SmallUiLiteralHooks.cs`의 기존 무의미한 `if (changed > 0) {}` 및 사용되지 않는 카운터 제거.

## C. 컴파일 실패 재발 방지

- `tools/check_csharp_delimiters.py` **신규**: C# 소스 파일의 문자열/주석 바깥 괄호·중괄호·대괄호 균형 검사.
- `tools/verify_workflow.py source`에 연결함. 기존 빌드 스크립트는 이미 이 검증을 `dotnet` 실행 전에 호출하므로 `CS1026` 유형의 단순 괄호 누락은 사전 단계에서 차단.
- `tests/WorkflowChecks/test_arenamode_build_rewrite.py` **신규**: 실제 오류 형태의 탐지 회귀 테스트 및 새 훅 연결·범위·툴팁 원본 호출 계약 검사.
- 기존 ArenaMode 회귀 테스트는 공통 훅 대신 **분리한 새 소스 파일**을 검사하도록 조정.
- **한계:** 괄호 사전 검사는 C# 의미 분석이나 컴파일러를 대체하지 못함. 이 실행 환경에는 `dotnet`/`csc`/`msbuild`가 없으므로 net48 클라이언트 DLL의 실제 컴파일은 **미실시**. 빌드 성공, dist 성공, 인게임 표시 성공으로 보고하지 않음.

## D. 검증 및 보존

- 113개 번역 프로필과 202개 Arena F12 설정, Arena 아이템·UI 번역 데이터는 **직전 ZIP과 변경 없음**.
- 소스 정적 검사·문서 검사·회귀 테스트 실행 기록은 사용자 전달 결과로 별도 고지.
- `note/update.md`, `note/README.md`, `note/번역지원모드목록.md` 변경 없음.
- 원본 모드 ZIP은 수정하지 않음.

## E. 남은 실사용 검사

1. 사용자 `BUILD_DISTRIBUTION.cmd`로 실제 클라이언트(net48)와 서버 빌드 및 dist 작성 확인.
2. 인게임에서 Arena 모드 선택/설명/변형 규칙/장비·맵 선택/점수판/강화 효과/툴팁을 단계별로 확인.
3. 언어 변경 `kr/kr-en` ↔ 그 외 언어, 경기 전환 및 재진입 시 UI 텍스트 복원 확인.
4. 기존 감사에서 별도 위험으로 기록된 `ARENA ZONE` 복원 관리 및 동적 경기 문구는 여전히 적용 완료로 판정하지 않음.

## F. 실제 사용자 빌드 오류 CS0012/CS0103 — 참조 규격에 맞춘 재수정

- 새 빌드 실패 증거: `src/ArenaModeUiHooks.cs(356,58)`의 `CS0012` (`UnityEngine.TextRenderingModule`에 정의된 `FontStyle`)와 `(356,71)`의 `CS0103` (`FontStyle` 식별 불가).
- 이 오류는 ArenaMode 원본 모드가 아닌 **애드온 전용 훅에서 직접** `__2.fontStyle == FontStyle.Bold`를 사용하여 생겼다. `SPT_Mod_Korean_Addon.csproj`의 기존 클라이언트 참조에는 `UnityEngine.TextRenderingModule.dll`이 없다. 사용자의 설치·빌드 방법 문제로 분류하지 않는다.
- 프로젝트 규칙에 따라 DLL/참조 추가나 빌드 스크립트 변경 **없이** 이미 참조된 `GUIStyle.fontSize`만 이용한다. 원본 ArenaMode 0.1.1 `ArenaMode.Client/Hud/ArenaScoreboardPresentation.cs`의 `_name` 스타일은 14pt이며 고정 다른 항목은 13/15/16/11/17/12pt다. 작은 화면에서 숫자 칸이 14pt로 줄어드는 경우에도 숫자만 번역 없이 원형 보존된다.
- 플레이어가 지정한 이름을 일반 문자열 번역 함수에 넣지 않는 기존 보호 분기와 `(YOU)` 접미사만 번역하는 동작을 유지한다. 실제 UI `Label(Rect,string,GUIStyle,Color)` 메서드에만 원래의 Harmony prefix를 적용한다.
- `tests/WorkflowChecks/test_arenamode_build_rewrite.py`에서 미등록 Unity FontStyle 참조가 재발하지 않는지 검사한다. 같은 파일의 기존 CS1026 검사도 유지한다. 총 9개 사용자 제공 문서의 원문 전체 및 저장소 내 문서와 바이트 동일성을 확인하였다.
- 검사 상태: `python tools/verify_workflow.py source`, `python tools/validate_translations.py`, `python tools/verify_workflow.py documents`, Python 회귀 테스트 **통과**. `dotnet`/`csc`가 이 작업 환경에 없으므로 **net48 실제 C# 컴파일·dist 생성·인게임 번역 표시는 미실시**. 사용자 컴파일 결과를 받기 전 `빌드 통과`로 판정하지 않는다.
- 문서 갱신 판단: 본 인계 기록은 갱신. `docs`의 번역 규격·공통 작업 절차는 기존 지침 그대로 적용, 변경 없음. `note/README.md`, `note/번역지원모드목록.md`, `note/update.md`는 번역 지원 범위·설치 방식·공개 변경점이 달라지지 않아 변경 없음. 번역 데이터, 원문 모드 ZIP, 클라이언트 프로젝트의 참조 및 배포 스크립트는 변경 없음. 삭제 파일 없음.
