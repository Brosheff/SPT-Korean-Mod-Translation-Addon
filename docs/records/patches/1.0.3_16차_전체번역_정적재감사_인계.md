# 1.0.3 개발 인계 — 16차 후보 전수 정적 재감사 및 기존 자동병기 오류 정정

## 증거와 대상

- 시작점: `SPT-Korean-Addon-1.0.3-Development-Batch15-Runtime-Locale-Fix-Source.zip` 전체 소스.
- 후보 기준: 12차 인계 ZIP에 들어 있던 1~11차 후보 **2,099건**. 12차 이후 번역 데이터 변경과 기존 후보 상태 재분류를 현재 파일로 교차 확인했다.
- 원본 패키지: Rook 1.2.1, Russian SF Pack 2.0.1, True North 4.0.29, ISB Special Forces 2.0.0, ISB Aishi 2.0.3, Epic's All in One 5.0.2. Under Fire / Dynamic Item Weights는 locale 원본이 아닌 C# 효과명/F12 후보로 분류되며 전체 F12 기능을 실게임에서 검증했다는 뜻이 아니다.
- **실제 서버의 `client/locale/en`, `client/locale/kr` 병합 결과 스냅샷 및 설치 후 게임 화면 전수 증거는 제공되지 않았다.** 그러므로 게임 내 적용 검증 완료라는 판정은 불가하다. VKS 부착물의 이전 영어 표시 및 Under Fire `Adrenaline`의 이전 표시 실패는 사용자 제공 인게임 증거로 유지한다. 15차 이후 성공 증거는 없다.

## 1. 검사에서 발견한 실제 문제

1. **수동 영문 아이템 병기:** 기존 번역 프로필 10개에서 아이템 `Name`의 `translation` 끝에 `\n(영문 이름)` 형태의 수동 병기가 **427건** 남아 있었다. `src/LocaleDisplayRules.cs`는 `kr-en` 아이템 이름에 원문을 자동으로 붙이므로 중복/낡은 영문 표시 위험이 있는 **확인된 데이터 작성 오류**다. 모두 *한국어 앞부분은 그대로 보존*, 수동 영문 후행부만 제거했다. 원본 `source`, 키/ID, `mod_id`, `match_mode`, 다른 채널은 수정하지 않았다. 세부 목록: `1.0.3_16차_자동병기중복_수정내역.json`.
2. **완료 상태 오분류:** 1~11차 후보 중 `source == translation`인 항목 **97건**(Rook 18, Russian SF 79)이 `translated`로 보고되어 있었다. 이를 **`source_kept`**로 바꾼 보정 인계 ZIP을 별도 생성했다. 기존 기록은 과거 인계 증거로 남긴다.
3. **같은 키의 서로 다른 번역 후보:** 기존 111개 프로필에서 대소문자 무시 비교로 서로 다른 `source` 또는 `translation`을 가진 키 그룹 **13개**를 확인했다. 그중 ISB/Aishi 공유 키 등은 서로 다른 후보가 원문에 일치하면 로더가 앞선 값을 선택한다. 이것만으로 13개 모두 적용 실패라고 증명되지는 않는다. 실제 병합 로케일/소유권 증거 없이 자동 삭제·우선순위 변경은 금지한다. 상세 후보: `1.0.3_16차_전수정적재감사.json`.

## 2. 원본 → 번역 JSON의 전수 정적 대조

| 대상 | 원본 비공백 영어 키 | 프로필 원문 일치 | 원본 대비 누락 | 원문 불일치 |
|---|---:|---:|---:|---:|
| Rook | 118 | 118 | 0 | 0 |
| Russian SF Pack | 327 | 327 | 0 | 0 |
| True North | 1,983 | 1,983 | 0 | 0 |
| ISB Special Forces | 28 | 28 | 0 | 0 |
| ISB Aishi | 1,049 | 1,049 | 0 | 0 |
| Epic's All in One | 1,547 | 1,547 | 0 | 0 |

위 표는 **업로드된 모드 ZIP의 원본 영어와 현행 `source`**의 일치만 뜻한다. 두 소스 모두 동일한 오래된 영어를 담고 있을 수 있으며, 다른 모드가 서버 로케일을 바꾸면 실제 비교값과 다를 수 있다. `ISB Special Forces`의 메타데이터 `locale: en`은 사용자 표시용 로케일 키가 아니므로 제외한다.

`translated`/`source_kept` 모두 **데이터 검토 상태**이지 인게임 적용 완료가 아니다. `ISB` 독립 결과 화면과 `Aishi` 목표 조건은 기존 보류 상태다.

## 4. 변경 내역 및 한계

- `translations/` 10개 JSON: 수동 영문 병기 제거 427개. 목록에 없는 번역 데이터는 수정하지 않았다.
- `tools/validate_translations.py`: 자동 아이템 이름에 수동 영문 병기가 들어오면 검사가 실패하도록 추가.
- `tests/WorkflowChecks/test_no_manual_item_name_bilingual.py`: 위 규칙의 전체 프로필 회귀 검사 추가.
- `tools/audit_patch103_candidates.py`: 후보와 번역 행·모드 원본의 키/원문·상태, 원문 유지 분류, 동일 키 충돌을 다시 확인하는 읽기 전용 검사 도구. 원본 ZIP 및 후보 인계를 명시적으로 입력받으며 **런타임 적용 검증 도구로 오인 금지**.
- `docs/` 인계 보고서, 전체 감사 JSON 및 상세 수정 내역 기록.
- `note/README.md`, `note/번역지원모드목록.md`, `note/update.md`: 지원 범위·설치 방식·정식 배포 버전 변경 없음. 공개용 업데이트 노트에 미검증 기능을 기록하지 않음.
- 이번 회차에 C# 로더/DLL은 변경하지 않음. C# 빌드, dist 패키징, 사용자 게임 내 실제 표시 검증: **미실시**.
- 특히 **15차 VKS/VSSK 원문 변형 수정도 아직 빌드·인게임에서 적용 성공을 확인한 자료가 없다.** `source_variants`라는 데이터/로더 연결만 확인된 상태다.

## 5. 남아 있는 적용 검증

1. 동일 버전 서버의 **실제 로케일 병합 결과**(`kr`과 `en`)가 없으면 1,658개 번역의 런타임 일치/적용을 전수 확정할 수 없다. 자료가 확보되면 `tools/audit_runtime_coverage.py`로 후보별 키·원문·다른 한국어 값·부모 로케일을 대조한다.
2. 충돌 후보 13그룹은 실제 런타임 키별 원문 및 선택된 번역을 확인한 뒤 그때만 해결한다.
3. 아이템 이름의 `kr-en` 자동 병기 결과는 데이터 중복을 제거했으나 실제 렌더링은 사용자 게임에서 별도 확인해야 한다.
4. ISB 결과 화면, Aishi 조건, Under Fire 이름 동기화 등 비일반 로케일 기능의 실제 실행 검증은 이번 정적 재감사로 대체되지 않는다.

## 6. 검사 게이트

- `python tools/validate_translations.py`
- `python tools/verify_workflow.py source`
- `python tools/verify_workflow.py documents`
- `python tools/verify_workflow.py handoff --manifest <보정된 handoff.json> --inventory <candidate_inventory.json>` (보류 2건 때문에 `--require-complete`를 쓰지 않음)
- `python -m unittest discover -s tests/WorkflowChecks -v`
- `python tools/audit_patch103_candidates.py --handoff <보정 인계 ZIP> --archives <원본 패키지 폴더> --report <보고서>`

검사 통과 후에도 게임 적용 검증 상태는 승격하지 않는다.
