# 부모 로케일 표시 패턴 재분석 — 1.7.14

기준은 배포된 Korean Patch Fix 2.1.1의 `SPT-Korean/locales/4.1.5/{en,kr,kr-en}.json`이다. 애드온 4.1.6이 실제로 참조하는 프로필이다. 별도 저장소의 오래된 소스나 이전 애드온의 출력은 기준으로 사용하지 않았다.

31,550개 키 전부를 비교했다. 한국어/한영병기가 다른 키는 4,738개다. **두 언어가 같은 키에도 이미 원문 이름과 퀘스트 제목 병기가 들어 있다.** 따라서 두 파일의 차이만 보는 분석은 충분하지 않다. 문장 번역의 옳고 그름을 평가한 것이 아니라 키의 표시 위치와 접두·접미 형식을 비교했다.

전체 키별 결과와 원본 SHA256은 `../locale-display-work/correction-1.7.14/parent-pattern-audit.json`에 보관했다. `tools/audit_parent_patterns.py`로 재생성할 수 있다. 설치본의 SPT 4.1.6 DB는 아이템·퀘스트·업적의 종류를 대조하는 데만 사용했다. 번역 자체는 부모 배포 데이터에서 읽었다.

## 실제로 확인한 주요 패턴

| 표시 위치 | 부모 한국어 | 부모 한영병기 | 이번 애드온의 규칙 |
|---|---|---|---|
| 일반 아이템 이름 | 한국어 이름 | `한국어 이름\n(원문 이름)` | `item_name` |
| 아이템 설명 | `[원문 이름]\n한국어 설명` | 왼쪽과 같음 | 두 언어 공통 머리말, 아래에 애드온 출처 추가 |
| 퀘스트 제목 | `한국어 제목 (원문 제목)` | 왼쪽과 같음 | `quest_title`, 두 언어 공통, 같은 줄 |
| 퀘스트 본문·진행/성공 대사 | 한국어 | 한국어 | 기본값, 전체 영어 덧붙이지 않음 |
| 일반 상인명·소개·메시지 | 한국어 | 대체로 동일 | 기본값, 특정 상인 예외를 다른 상인에게 확대하지 않음 |
| 업적 제목 | 한국어 제목 | `한국어 제목 (원문 제목)` | 원본 업적 정의로 확인한 `achievement_title`만 적용 |
| 업적 조건의 개별 표시 키 | 한국어 조건 | `한국어 조건\n(원문 조건)`인 패턴 | 원본 조건 ID로 확인한 `achievement_condition`만 적용 |
| 아이템 단축명 | 대체로 번역 단축명 또는 원문 | 대체로 동일 | 기본값, 모든 ShortName에 원문을 추가하지 않음 |
| 일반 UI·버튼·설정·안내 | 대체로 한국어 | 대체로 동일 | 모드 자체 UI/F12/알림/메일은 병기 없음 |

대표 근거:

- `5447a9cd4bdc2dbd208b4567 Name`: 한국어 이름 뒤의 `\n(Colt M4A1 5.56x45 assault rifle)`은 한영병기에만 있다.
- 같은 ID의 `Description`: `[Colt M4A1 5.56x45 assault rifle]\n`은 **두 언어에 모두** 있다. 설명 영문 전체가 아니다.
- `5936d90786f7742b1420ba5b name`: **두 언어 모두** `데뷔 (Debut)`. 줄바꿈 형식이 아니다.
- 같은 퀘스트의 `description`, `successMessageText`: 두 언어에서 같은 한국어 본문이다.
- `54cb50c76803fa8b248b4571 Nickname`: 두 언어 모두 `프라퍼`다.
- 실제 DB 퀘스트 558개 중 555개의 제목이 두 언어 공통 인라인 병기다. 나머지 3개는 제목 한국어만 있다. 모든 부모 행이 완벽히 통일되어 있다고 주장하지 않는다.
- 실제 아이템 DB와 겹치는 설명 4,553개는 두 언어가 전부 같고, 그중 4,025개가 정확한 `[동일 ID의 영문 Name]` 머리말을 갖는다. 주머니·내부 컨테이너·빈 설명 등에도 무조건 머리말이 있다고 일반화하지 않는다.
- 실제 업적 정의와 겹치는 제목 53개 중 50개가 한영병기에서만 다른 값이다. 원문 자체가 `PMC` 같은 동일 문자열이면 반복하지 않는다.

## 별도로 확인한 패턴과 일반화하지 않는 예외

이 항목도 조사했다. 최초 요청에 없었다는 이유로 누락하지 않았으며, 아래의 개별 예외를 일반 UI 전체에 확대하지 않는다.

- **스킬 설명**: 한영병기에 `[Advanced Modding]\n`, `[Endurance]\n`처럼 스킬의 영문 이름 머리말이 생긴다. 원문 설명 문장을 통째로 붙이는 방식이 아니다.
- **지역 이름/설명**: `지역 이름 (English)`와 `[Factory, 공장]\n설명` 같은 방식이 있다. 짧은 지역 키에는 줄바꿈 병기도 있어 키 종류별 차이가 있다.
- **탈출구·맵 이동·택시 목적지**: 줄바꿈 괄호, 같은 줄 괄호, 공백 없는 괄호 등 위치별 패턴이 있다. `Description`이라는 글자만 보고 아이템 설명으로 분류하면 안 된다.
- **포격 경고**: 전체 경고문 원문이 아니라 `\n(Tarcone)` 같은 **장소명만** 덧붙인 18개 키가 있다. 모든 모드 알림에 영문 문장을 붙이는 근거가 아니다.
- **일부 상인**: Lightkeeper·BTR Driver의 일부 필드에만 병기 예외가 있다. 프라퍼 등 일반 상인명/소개에는 적용되지 않는다.
- **ShortName·의류**: 일부 신규 항목의 단축명, 3개 의류 설명, 프레스티지 완장 등은 일반 규칙과 다르다. 모든 모드 단축명/설명으로 확대하지 않는다.
- **기타**: 언어 이름, 색상 필터 이름, KDR 약어, 일부 지역/분류명, 괄호 없는 줄바꿈, 슬래시 표기가 있다. 대부분은 특정 키의 편집 예외다.
- **자막**: 다른 값으로 검출된 58개는 JSON 문자열 내부 공백만 다르고, 파싱한 자막 내용은 같다. 병기 규칙으로 세지 않는다.

부모의 서로 다른 값 4,738개를 형식으로 나누면 줄바꿈 괄호 4,355, 공백 있는 인라인 185, 공백 없는 인라인 26, 괄호 없는 줄바꿈 14, 슬래시 2, 대괄호 머리말 77, 특정 표기/편집 차이 21, 자막 JSON 공백 차이 58개다. 이 수치는 같은 문자열을 공유하는 설명 머리말·퀘스트 제목을 포함하지 않는다.

## 적용 경계

부모 payload 자체는 변경하지 않는다. 부모의 지역·스킬·상인별 예외는 부모가 계속 관리한다. 애드온에서는 **실제 번역 대상의 의미가 확인된 분류만** 사용한다. 모드 고유 버튼, 옵션, 지도 내부의 임의 라벨을 부모 지역명과 같다고 추측해 병기하지 않는다.

아이템 설명 끝의 `(mod_name)`은 부모의 규칙이 아니라 모드 아이템 식별을 위한 애드온 규칙이다. 언어와 무관하게 한국어/한영병기에 모두 표시한다.

원문 이름은 같은 프로필의 이름 행 `source`를 우선 사용하고, 없으면 부모 영어 사전/서버의 원문 이름 키를 참조한다. 별도 키 구조는 `name_key`로 연결한다. 원문을 얻지 못하면 설명 영문을 이름으로 대체하거나 추측하지 않고, 모드 출처는 유지하며 `missing_item_name_sources`에 기록한다. 한국어만 제공하는 미등록 다른 모드까지 자동으로 가공하지 않는다.
