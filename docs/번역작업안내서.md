# SPT 모드 번역 작업안내서

이 문서는 현재 애드온의 번역 **구현 방법**을 설명하는 현행 기술 지침이다. 1.7.14는 이 지침의 도입 이력이며 현재 애드온 버전이 아니다. **2026-10-12 사용자가 확정한 세력명 영문 표기**를 유지한다. 폴더 이름 `...1.7.11`로 현재 DLL 버전을 추정하지 않는다.

아래 데이터·코드 경로는 저장소 루트 기준이다. 클라이언트 코드는 `src/`, GPT 작업 지침은 `docs/`, 사용자 공개용 안내는 `note/`에 둔다. 이 문서와 연결된 기술 문서 링크는 `docs/` 기준이다. 일반 사용자 안내 문서는 `note/`에서 배포·열람하며, 설치 ZIP에는 런타임 파일만 포함하고 `docs/`, `note/`, C# 소스 및 개발 중간 기록을 넣지 않는다. 설치 ZIP만 전달받았다면 없는 소스를 추측해서 새 엔진을 만들지 말고, 데이터로 가능한 작업부터 처리한다.

## 매 답변 전 확인 — 생략 금지

매 응답 전 **`docs/AGENTS.md`의 단일 문서 열람 순서**와 [`응답전_필수확인.md`](응답전_필수확인.md)의 증거 게이트를 따른다. 이 기술 문서에 별도의 열람 순서를 만들지 않는다. 특정 번역은 실제 원본·프로필·로더의 매칭 조건 및 최신 실행 증거로 확인하고, JSON 검사만으로 인게임 적용을 주장하지 않는다.

## 0. 필수 상위 절차

**새 모드 분석·번역·소스 파일 전달·배포물 제작을 시작하기 전에 [`모드번역_작업절차.md`](모드번역_작업절차.md)를 먼저 읽는다.** 이 문서는 구체적인 기술 경로와 번역 규칙을 설명하며, 단계별 작업의 인계·시간초과 방지 분할·최종 원본 역대조·배포물 구분은 상위 절차가 담당한다. 각 모드에서 발견한 실제 표시 후보와 훅 적용 상태는 [`번역대상_인계기록_양식.md`](번역대상_인계기록_양식.md) 형식으로 관리한다.

**추가 제한:** 새 모드가 자체 로케일이나 웹 UI를 제공하더라도 원본 모드 파일을 교체하는 `extras`나 별도 설치 패치를 임의로 제작하지 않는다. 기존 애드온 내부 연결을 먼저 확인하고, 필요한 경우 클라이언트/서버 훅을 정확한 지점으로 확장한다. 기존 규격으로 해결되지 않으면 미완료로 보고하며 임의의 우회 구조를 만들지 않는다. 번역 데이터 작성, 적용 코드 연결, 빌드, 배포 포함, 인게임 확인을 각각 구별한다.

**빌드와 문서 검사의 분리:** `BUILD_DISTRIBUTION.cmd`는 프로젝트 자신의 폴더를 기준으로 동작하며 **게임 설치 경로를 요청·탐색·사용하지 않는다.** 클라이언트·서버 빌드에 필요한 호환 DLL은 프로젝트의 `references/client`, `references/server`에서 참조한다. 외부 참조 디렉터리는 명시적인 `ADDON_REFERENCE_ROOT`나 첫 번째 인수로만 지정할 수 있다. 필요한 DLL이 없을 때에는 목록을 출력하고 중단하며, 게임 설치 폴더를 자동으로 검색하지 않는다. 상세 파일 목록은 `references/README.md`에 기록한다. `docs/`, `note/`는 DLL 컴파일의 필수 입력이 아니며 누락되었다고 빌드를 중단하지 않는다. 문서 완성도는 별도로 `python docs/tools/verify_workflow.py documents`로 검증한다. 번역 작업 종료 때 두 폴더를 점검할 의무는 그대로 유지된다.

## 0-1. 작업 종료 시 지침·기록·공개 문서 분리 — 필수

**문서 갱신의 수행 시점·판정과 대상별 갱신 트리거는 `모드번역_작업절차.md` 7절이 유일한 기준**이다. 번역·코드·지원 범위·버전·배포 방식 변경 시 그 절에 따라 기술 지침, `docs/records/work-history/`의 작업별 인계 기록, `note/README.md`, 지원 목록, 공개 업데이트 노트의 필요성을 점검한다. 변경 사항이 없으면 억지로 수정하지 않는다. `note/update.md`는 개발 중간 기록이 아니라 직전 **실제 공개 버전**과 이번 최종 배포본의 차이만 쓴다. 공지 형식과 설치 안내의 승인 조건은 `배포_업데이트노트_작성지침.md`가 담당한다. 이 기술 문서는 별도의 공개 노트 템플릿이나 문서 갱신 순서를 정의하지 않는다.

## 1. 먼저 읽고 확인할 것

1. 사용자에게 받은 **최신 소스/배포본/번역 파일**을 기준으로 삼는다. `_dist`나 과거 백업으로 현재 파일을 되돌리지 않는다.
2. **현행 규격**은 `TRANSLATION_FORMAT.md`와 현재 `src/LocaleDisplayRules.cs` 등 소스에서 확인한다. `docs/records/audits/PARENT_PATTERN_AUDIT_1.7.14.md`와 `docs/records/audits/LOCALE_DISPLAY_1.0.0_KO.md`는 필요할 때 이력·참고 자료로 읽고, 과거 검증 결과를 현재 결과로 대신하지 않는다. 문서 필수 열람 범위는 `docs/AGENTS.md`에서 확인한다.
3. 대상 모드의 기존 `translations/*.json`, `config-ui/*.json`, 관련 최신 작업 메모를 찾는다. `mod_id`/plugin GUID로도 검색한다. 1.7.16부터 같은 모드의 UI·알림·로케일은 한 JSON의 채널로 관리한다. `Small UI -`, `UI Alerts -` 같은 분리 파일을 재생성하지 않는다. config-ui와 native-locales는 별도 규격으로 유지한다. **현행 파일명·프로필 ID·채널은 실제 `translations/*.json`에서 직접 확인한다.** 이전 통합 내역 문서 `MERGED_TRANSLATIONS_1.7.16.md`는 제공되지 않아 과거 파일 대응 관계는 미확인이다.
4. 원본 모드의 실제 로케일 파일 또는 화면에 문자열을 넘기는 코드를 별도로 확보해 대조한다. 폴더 이름보다 csproj/메타데이터/배포 DLL의 실제 버전을 우선한다.
5. 부모 규칙을 변경해야 한다면 사용 중인 SPT Korean Locale Patcher의 해당 SPT 버전 세 언어 파일을 직접 비교한다. **kr과 kr-en의 차이뿐 아니라 두 파일에 공통으로 들어 있는 영문도 확인한다.**

용어는 지정된 용어표와 기존 확정 번역을 우선한다. 프롬프트의 참고 파일이 없으면 존재한다고 가정하지 않고 현재 제공된 레퍼런스를 사용하며, 필요한 미확인 사항만 보고한다.

사용자가 제공한 1.7.13 코드 분석에서 번역 경로와 조사 범위를 이 문서에 통합했다. 당시의 프로필/항목 수는 고정 규격이 아니므로 작업 시 다시 집계한다. 당시 설명 중 퀘스트 제목의 줄바꿈 병기, 한국어 설명의 출처 생략, 일반 UI의 병기 정책은 현재 1.7.14 규칙으로 수정했다.

## 2. 텍스트가 나오는 위치에 따라 경로 선택

| 대상 | 데이터 위치/채널 | 확인할 기존 코드 |
|---|---|---|
| 아이템·퀘스트·상인·업적 로케일 키 | `translations/<mod>.json` → `locale` | `src/ClientLocaleModOverlay.cs`, `src/LocaleDisplayRules.cs` |
| 로케일 원문은 있지만 키가 불안정한 기존 지원 대상 | `locale_source_fallback` | 정확한 원문 일치와 부모 번역 보호 조건 확인 |
| 모드가 실제로 조회하는 추가 UI 로케일 키 | `locale_additions` | 조회 코드에서 실제 키 확인, 임의 키 생성 금지 |
| 부모 아이템에 이름/설명 일부를 붙이는 기존 복제 아이템 | `locale_clone_suffix` | `parent_key`, 추가 원문, 실제 생성 코드를 확인 |
| F12 일반 설정의 이름·분류·설명·선택지 | `config-ui/<plugin GUID>.json` | `src/ConfigManagerProfiles.cs`, `src/ConfigurationManagerHooks.cs` |
| F12 CustomDrawer 내부의 버튼/문구 | 기존 전용 처리 | `src/F12CustomDrawerHooks.cs`; 일반 설정 JSON만으로 된다고 가정하지 않음 |
| C# 문자열로 직접 그리는 모드 UI | 주로 `small_ui`, 모드별 전용 채널 | `src/SmallUiLiteralHooks.cs`, `src/ModUiLiteralHooks.cs`, `src/DynamicMapsUiHooks.cs` |
| 화면 알림·오류·팝업 | `notifications`, `error_screens`, 기존 `dialogs` 등 | `src/DisplayHooks.cs`의 plugin GUID 연결과 호출 위치 |
| NPC 직접 메일 | `npc_messages` | 서버 `MessageTranslator.cs`, `ServerTextRules.cs`, 정확한 `trader_id` |
| USER/SYSTEM 직접 메일 | `server_messages` | 서버의 실제 전송 경로, `exact`/`segment` |

**JSON에 새 채널명이나 문장을 썼다는 사실만으로 게임에 적용되지 않는다.** 실제로 그 프로필 ID와 채널을 읽는 코드가 있어야 한다. `reference_only`는 게임 적용 경로가 아니다.

### 2-1. 아이템 DB 외에도 조사할 표시 문자열

모드 전체 번역을 요청받았다면 아래를 조사한다. 사용자가 상인 정보만 요청하는 등 범위를 한정했다면 그 범위만 처리한다.

- 글로벌 locale: 아이템/의류 이름·단축명·설명, 상인 프로필, 세력/역할 표시명(`ScavRole/...`), 업적, 문서·쪽지·페이지 본문, 택시 목적지·대사, 모드가 실제로 주입하는 기타 키.
- 퀘스트: `name`, `description`, `startedMessageText`, `successMessageText`, `failMessageText`, `acceptPlayerMessage`, `declinePlayerMessage`, `completePlayerMessage`, `changeQuestMessageText`, 그리고 별도 `<objectiveId>` 키의 목표 문구. 존재하지 않는 메시지 필드는 만들지 않는다.
- 서버: 직접 NPC 우편, USER/SYSTEM 우편, 서버에서 생성하여 클라이언트 화면에 전달하는 오류 문구.
- 클라이언트: 일반 F12 ConfigEntry, CustomDrawer, 알림, 팝업, TMP/Text, GUI/GUILayout, 컨텍스트 메뉴·툴팁·자체 에디터.
- 모드의 자체 localization 서비스와 `lang`/`locales` 파일, Awake/생성자에서 배열·Dictionary·캐시에 저장해 나중에 그리는 문자열.

각 후보는 **원본 파일/키 또는 타입·메서드 → 실제 화면/발신자 → 기존 적용 채널 → 데이터만 수정할지 여부**를 기록한다. 코드에서 영어를 찾았다는 사실만으로 번역 대상으로 확정하지 않는다. `<size>`, `<align>`, `<width>`, `<color>` 등 리치텍스트의 구조와 치환 변수도 보존한다.

### 2-2. 데이터 추가와 코드 연결의 경계

| 발견한 경로 | 우선 작업 | 코드 검토가 필요한 조건 |
|---|---|---|
| 글로벌 locale의 실제 키 | 기존 모드 locale 프로필에 원문/번역 추가 | 특수 생성 방식이나 원문 일치가 기존 방식으로 처리되지 않을 때 |
| 일반 F12 ConfigEntry | 정확한 GUID/section/key로 config-ui 추가 | CustomDrawer 등 일반 표시 객체를 거치지 않을 때 |
| 직접 NPC/USER/SYSTEM 메일 | 기존 서버 전송 훅과 규칙의 범위 확인 후 JSON 추가 | 다른 전송 API·TemplateId·별도 전송 경로를 사용할 때 |
| 알림/전체 화면 오류 | `DisplayHooks.ProfileByPluginGuid`와 채널 확인 | 새 GUID이거나 기존 표시 메서드를 거치지 않을 때 |
| small_ui/전용 팝업 | 기존 대상 타입·메서드와 profile ID 확인 | 현재 등록된 표시 지점 밖일 때 |
| 자체 다국어 시스템 | 기존 로케일 공급/언어 연결을 활용할 수 있는지 확인 | 새 어댑터가 실제로 필요할 때만 최소 확장 |

새 모드라는 이유만으로 새 C# 코드를 작성하지 않는다. 반대로 연결이 없는 JSON을 추가한 뒤 번역 완료라고 보고하지도 않는다. 필요할 때 기존 구현의 연결만 확장하고, 식별자·경로·로그·게임 로직 문자열에는 번역 훅을 만들지 않는다.

### 2-3. 원문 공급원 → 최종 로케일 → 애드온 로더 실증 절차 (필수)

단일 영어 JSON만 읽어 `source`를 일괄 교체하면 **Aishi 2.0.4처럼 서버 등록과 언어별 최종화가 다른 원문을 공급할 때** 기존 번역이 사라질 수 있다. 다음 순서를 **해당 키를 수정하기 전**에 실행한다.

1. **검색 대상을 넓힌다.** 대상 모드 버전의 `en/kr` 등 로케일, 상인·아이템·퀘스트 정의, C# 등록 함수, DLL 문자열, 서버 transformer, 직접 텍스트 할당을 모두 검색한다. `AddTraderToLocales`, 후처리 함수, Dictionary/캐시 덮어쓰기 등 동일 키를 쓰는 모든 경로를 찾는다.
2. **키별 공급원 표를 만든다.** 각 후보에 `키 / 표시 화면 / 실제 공급 파일·메서드 / 원문 영어 / 실행 언어·조건 / 호출 순서 / 기존 값 보존·덮어쓰기 조건`을 기록한다. 동일 키·동일 버전에서 값이 둘 이상이면 한쪽을 임의로 삭제하거나 과거 버전으로 분류하지 않는다.
3. **최종값을 유도하고 증거 등급을 표시한다.** `최초 등록 → 후처리 → 부모/다른 모드 병합 → 서버 응답 → 클라이언트 훅`의 조건 분기를 확인한다. 결과는 `정적 추론 최종 영어`와 `실제 서버 스냅샷/인게임 관찰 영어`로 **별도 기록**한다. 실행 자료가 없으면 `런타임 미확인`이라고 쓴다.
4. **로더에 실제 입력될 값을 시험한다.** `key + 정적 확인 원문(가능하면 실제 raw locale) + 언어(kr/kr-en/en)`로 후보 일치, 상속되는 `match_mode`, 파일 정렬 순서, 첫 일치 후보, 부모 번역 보존, 캐시/언어 전환을 대조한다. 기존 로더의 호출 경로를 재사용하거나 동일 규칙임을 확인한 테스트에서 **선택 한국어/원문 유지 여부**를 기록한다. `source == 원본 en.json`만으로 통과하지 않는다.
5. **원문 갱신 시 조건을 확인한다.** 원본 모드 파일은 건드리지 않는다. 번역 프로필의 `source`만 **최신 모드의 확인된 실제 값**에 맞춰 필요 최소한으로 갱신한다. `source_variants`는 `TRANSLATION_FORMAT.md`에서 요구하는 실제 화면 또는 서버 스냅샷 증거가 있는 경우에만 사용한다. 코드상 다른 공급원만 확인했으면 후보/미확인으로 기록하고 임의의 변형이나 구버전 호환 프로필을 생성하지 않는다.
6. **원본→애드온/애드온→원본 양방향 대조:** 원본의 사용자 표시 후보가 번역·원문 유지·비대상·보류 중 하나인지, 등록 번역이 실제 채널·훅에 연결되는지 검사한다. 실행하지 못한 인게임·빌드 검증은 정적 테스트 통과와 분리한다.

**적용 사례:** Aishi 상인의 `FullName`·`FirstName`·`Description`은 `en.json`뿐 아니라 `aishi_trader.cs`의 상인 등록과 `AishiLocaleFinalization.cs`의 기존 값 보존 조건을 대조해야 한다. 정적 조건이 가리키는 값은 확인할 수 있어도, 실제 사용자의 서버에서 최종 선택된 값까지 검증했다고 주장하지 않는다. 기존 구버전용 `Compatibility.json`을 복원하여 우회하지 않는다. 기록 표는 `번역대상_인계기록_양식.md` B-1절을 따른다.

## 3. 아이템과 퀘스트 번역 작성법

`source`에는 실제 원문을 공백·태그·기호까지 보존하고, `translation`에는 번역 본문만 작성한다. 모드명은 프로필 상단 `mod_name` 한 곳에서 관리한다.

```json
{
  "schema_version": 1,
  "target_spt": "4.1.6",
  "mod_id": "example.mod",
  "mod_name": "Example Mod",
  "channels": {
    "locale": [
      { "key": "example_item Name", "source": "Example rifle", "translation": "예시 소총", "match_mode": "item_decorated" },
      { "key": "example_item ShortName", "source": "Example", "translation": "예시" },
      { "key": "example_item Description", "source": "A rifle.", "translation": "소총입니다." },
      { "key": "example_quest name", "source": "First Step", "translation": "첫걸음", "match_mode": "exact", "display_type": "quest_title" }
    ]
  }
}
```

위 ID는 설명용이다. 실제 추가 시에는 원본에서 확인한 키만 사용한다.

표시는 코드가 만든다:

- 아이템 이름: 한국어는 `예시 소총`, 한영병기는 `예시 소총\n(Example rifle)`.
- 설명: **두 언어 모두** `[Example rifle]\n소총입니다.\n(Example Mod)`.
- 퀘스트 제목: **두 언어 모두** `첫걸음 (First Step)`.
- ShortName, 퀘스트 메시지, 상인명/소개: 기본적으로 번역 본문만 표시한다.
- 1.7.16 사용자 요청: 실제 퀘스트 설명은 `quest_description`, 업적 설명은 `achievement_description`으로 지정해 두 한국어 설정에서 본문 끝에 `\n(mod_name)`을 자동 표시한다. 아이템 설명의 기존 출처는 유지한다. 새 출처 적용 대상을 목표·대사·완료 메시지로 넓히지 않는다. 데이터에 모드명을 직접 쓰지 않는다.
- **퀘스트 목표는 두 언어 공통 `한국어 목표\n(영문 목표)`다. 1.7.15부터 실제 퀘스트 conditions에서 확인한 목표 행에 `display_type: "quest_objective"`를 명시한다.** 제목·설명·목표를 구분한다. 과거 재감사 문서 `QUEST_PATTERN_REAUDIT_20261003.md`는 현재 제공되지 않는다. 현행 규칙은 `TRANSLATION_FORMAT.md`와 `src/LocaleDisplayRules.cs`에서 확인하고, **새 목표의 조건 ID는 반드시 원본 모드 정의/실제 conditions로 별도 검증한다.** 모든 bare ID를 목표로 분류하거나 수동 원문을 저장하지 않는다.
- 업적 제목은 확인된 `achievement_title`에 한해 한영병기에서 인라인 원문을 추가한다. 업적 조건은 실제 조건 ID를 확인한 `achievement_condition`에 한해 줄바꿈 병기한다. 업적 설명에는 코드가 모드 출처만 붙이며 영문 본문은 병기하지 않는다.

원문 유지 탄약처럼 `source`와 `translation`이 같으면 이름을 반복하지 않는다. 모델명·탄종·약어, `(50발)`, `(FMJ)`, 원래 내용의 괄호와 문단은 지우지 않는다.

`translation_bilingual`은 만들지 않는다. `[원문 이름]`, 전체 원문 접미부, `(모드명)`도 번역 본문에 직접 넣지 않는다. 기존 항목을 정리할 때는 동일 원문/동일 모드명으로 확인한 자동 표시 부분만 제거하고 모든 괄호를 정규식으로 지우지 않는다.

**게임 화면에서 원본 ZIP과 다른 영어 원문이 확인된 아이템:** 원본 `source`를 훼손하거나 전체 로케일 원문 검사를 해제하지 않는다. 실제 화면에서 읽은 문자열과 원본 로케일 키의 관계를 검토해 **그 키에만** `source_variants`로 검증된 대체 원문을 추가한다. 이름·설명을 각각 따로 검증하고, 이름의 한영병기와 설명의 `[원문 이름]`도 실제로 일치한 변형을 사용하도록 기존 로더를 갱신한다. 자세한 허용 조건과 VSK/VKS 재발 사례는 `TRANSLATION_FORMAT.md`를 따른다. 변형 데이터는 새로운 C# 코드가 포함된 DLL을 빌드해야 적용된다. **전체 서버 원문 스냅샷 없이 모든 번역 적용 성공을 선언하지 않는다.**

`locale`의 첫 행은 `match_mode`를 명시한다. 뒤 행은 이전 값을 상속하므로 삽입 위치와 전환 지점을 확인한다. `display_type`은 상속되지 않는다. 대소문자도 원본 그대로 유지한다.

일반 `Name`/`Description`은 아이템 규칙으로 분류되지만 상인/퀘스트 그룹은 제외된다. 단독 퀘스트 제목, 대문자 업적, 소문자 의류, 접미사가 없는 의류 키는 원본 정의로 확인하여 `display_type`을 명시한다. 설명의 이름 키가 다른 경우 `name_key`를 사용한다. 표시용 영어 이름을 추측하거나 설명 원문을 대신 쓰지 않는다.

## 4. 코드에 직접 적힌 클라이언트 UI

1. 원본 문자열의 실제 표시 지점을 찾는다. 로그·파일명·Config.Bind 식별자·저장 데이터는 번역 대상과 분리한다.
2. 기존 훅의 assembly/type/method와 profile ID/channel이 그 지점을 포함하는지 확인한다.
3. 이미 포함하면 **해당 JSON의 source/translation만 추가**한다. 예: MunitionsExpert의 `Armor damage`는 `MunitionsExpert.json`의 `small_ui`로 처리한다.
4. 미지원 지점이면 기존 훅에 정확한 대상만 최소 추가한다. 그 필요성과 대상 메서드를 기록한다. 새로운 범용 엔진, 모든 어셈블리 메서드 훑기, Unity GUI 전역 치환으로 해결하지 않는다.
5. `kr`와 `kr-en`은 동일한 한국어 UI, 그 외 언어는 원문이다. 문장 길이를 보고 영어를 추가하지 않는다.

문자열이 생성 시점에 저장되는 UI는 언어 변경 때 원문에서 다시 계산해야 한다. 이미 번역한 표시값 뒤에 계속 덧붙이지 않는다. 대상 메서드가 없거나 원문이 변경되면 기존 기능을 유지하고 번역을 건너뛰어야 한다.

### 4-1. 전용 구현을 범용 기능으로 오해하지 않기

- `SmallUiLiteralHooks`는 assembly/type/method/parameter count 등 확인된 범위로 제한되어 있다. 이미 지원하는 지점인지 먼저 확인한다. 특정 타입의 생성 람다를 포함하는 설정이 있어도 어셈블리 전체를 패치해도 된다는 뜻이 아니다.
- `dialogs`는 현재 Vagabond의 `UIMessageService.ConfigureDialog`에 연결되어 제목·본문·주 버튼·보조 버튼을 처리한다. 다른 모드의 팝업이 같은 채널을 자동으로 사용하는 것은 아니다.
- `server_errors`는 현재 Vagabond/Croupier 프로필의 명시적 원문 처리다. 클라이언트 GUID로 식별할 수 없는 서버 오류를 모두 처리하는 범용 채널로 간주하지 않는다.
- Dynamic Maps의 `custom_ui`/`map_content`는 `src/DynamicMapsUiHooks.cs`의 **1.2.1 버전 검사**와 지정 메서드에 연결되어 있다. 다른 버전의 번역 문장을 추가해도 훅이 건너뛰면 표시되지 않는다. 버전 검사를 무작정 제거하지 않는다.
- Weapon Camo & Stickers 계열은 `ui_literals`, `external_ui_literals`, `equipment_placements`와 `src/ModUiLiteralHooks.cs`를 사용한다. 화면 리터럴 외에 먼저 생성된 배열/Dictionary 상태를 복구하는 기존 처리도 확인한다.
- F12 자체의 Reset/Search/Enabled 같은 문구는 `src/ConfigurationManagerHooks.cs`, 일부 CustomDrawer 문구는 `src/F12CustomDrawerHooks.cs` 안의 전용 사전/처리에 있다. 모든 F12 문자열이 config-ui JSON에서 온다고 가정하지 않는다.
- PitFireTeam은 자체 localization 경로에 파일을 공급하고 언어 해석을 연결한다. UI 텍스트를 직접 패치하는 방식이 아니다. 다른 모드가 자체 로케일을 지원해도 파일 경로·로더·키·언어 갱신 방식이 같다고 가정하지 않는다.

## 5. F12·알림·메일의 주의점

- F12는 `plugin_guid + section + key`와 원문 표시값으로 연결한다. 빈 section/key가 실제로 존재하면 그대로 쓴다. 저장된 `.cfg` 키와 값, enum 내부 값은 번역하지 않는다.
- `translation_display_name`, `translation_description`, categories/values의 `translation`만 작성한다. `_bilingual` 필드를 추가하지 않는다.
- F12를 열면 나오는 `_discovered-settings.json`/`_templates`는 조사 자료다. 적용 파일은 `config-ui` 바로 아래의 일반 JSON이다.
- 알림은 허용된 호출자 GUID에만 적용한다. 프로필을 만들기 전에 기존 연결을 확인한다.
- 알림은 `DisplayWarningNotification`, `DisplayMessageNotification`, `DisplayErrorNotification`, 전체 화면 오류는 `PreloaderUI.ShowErrorScreen`의 실제 호출 경계를 확인한다. 같은 문장을 쓰는 다른 모드에 번역이 번지지 않도록 호출자 제한을 유지한다.
- 동적 문장은 `{0}`, `{count}` 등 치환 변수를 보존한다. 기존 `exact`, `template`, `segment`, `segment_template`, `regex_segment` 중 실제 생성 방식에 맞춘다. regex는 .NET 문법이다.
- 메일은 서버 전송 시점에 번역된다. 이미 저장된 메일이 언어 변경만으로 다시 번역된다고 주장하지 않는다. TemplateId 메일은 기존 로케일 경로를 따른다.
- NPC 직접 메일은 `MailSendService.SendDirectNpcMessageToPlayer`의 traderId와 실제 화자를 추적해 `npc_messages`에 등록한다. USER/SYSTEM 직접 메일은 `SendUserMessageToPlayer`/`SendSystemMessageToPlayer`와 `server_messages`로 처리하며 trader_id를 붙이지 않는다. 일반 동적 규칙의 다섯 match_mode를 server_messages에 그대로 확장하지 않는다. 이 채널은 exact/segment만 허용한다.
- PitFireTeam의 `krx.json`/`kren.json`은 현재 같은 한국어 내용이다. 호환 별칭 두 파일을 유지하되 한쪽에 원문을 덧붙이지 않는다.

### 5-1. 동적 문자열 규칙 선택

| match_mode | 사용 조건 |
|---|---|
| exact | 전체 문자열이 고정 원문과 일치 |
| template | 전체 문장의 일부가 `{0}`, `{name}` 등 변수 |
| segment | 긴 문자열 속 고정 구간만 치환 |
| segment_template | 긴 문자열 속 변수 포함 구간만 치환 |
| regex_segment | 소스에서 확인한 조립 규칙을 .NET 정규식 이름 캡처로 표현 |

예: `Your {0} isn't coming back.`는 `{0}`을 보존한 템플릿으로 번역한다. 런타임 아이템명·숫자·위치 자체를 정규식에 고정하지 않는다. 먼저 고정/템플릿 방식으로 가능한지 확인하고, 정규식은 실제 생성 규칙을 알 때만 쓴다. `exclusive_group`은 같은 패스의 대안 패턴 중 한 규칙만 적용하는 용도이며, 모드/화자 제한을 대신하지 않는다. 이 표는 일반 클라이언트 텍스트 및 NPC 메시지용으로, locale의 exact/item_decorated와 구분한다.

**2026-10-12 사용자 확정 규칙:** `BEAR`, `USEC`, `RUAF`, `UNTAR`는 번역 본문에서도 **영문 대문자 그대로** 표기한다. 이전 작업안내서의 `베어`, `유섹`, `루아프`, `운타르` 표기는 폐기한다. 다른 명칭은 아래 기존 번역 기준을 유지하되, 추가 변경은 사용자의 명시적인 확정 표기를 우선한다. 아래 표는 부모 로케일이 동일하게 표기된다는 주장이나 기존 번역 JSON 전체가 수정되었다는 뜻이 아니다.

| 원문 세력명 | 번역 본문 표기 |
|---|---|
| BEAR | BEAR |
| USEC | USEC |
| Scav / Scavs | 스캐브 |

- `베어(BEAR)`처럼 번역 본문에 한글 표기나 원문을 중복해서 수동 병기하지 않는다. 표시 코드가 붙이는 원문 이름 및 `mod_name` 출처는 이 세력명 표기와 별개다.
- 이번 보정은 **문서의 향후 작업 기준만** 변경한다. 기존 애드온의 번역 JSON 내용은 수정하지 않았으며, 대상 모드 번역 시 실제 데이터의 이전 표기를 따로 대조한다.

## 7. 검증과 마무리

**합격 게이트:** (a) 현행 지원 원본의 사용자 표시 후보 전체 분류, (b) 등록된 모든 번역의 키·원문·채널·매칭 분기 대조, (c) 오류 발견 시 동일 원인 사용 프로필 전체 재검사, (d) 현재 버전의 정상 번역 회귀 대조, (e) 신규 설치와 덮어쓰기 후 로딩 대상 검사. 각 검사는 `대상 N / 확인 N / 실패 N / 미확인 N`과 증거 파일을 남긴다. 다른 모드의 원본이 제공되지 않으면 그 모드의 실제 출력 검증은 **미확인**이지만, 기존 애드온 전체 프로필 및 공통 훅의 정적 영향 검사는 수행한다. 구버전 전용 영어를 보존하려고 호환 파일·스크립트를 다시 만들지 않는다.

**회귀 입력 세트:** 현행 기존 키+영어, 신버전 키+최종 영어, 동일 키의 복수 공급원, 중복 후보, 키 없음, `kr → kr-en → en → kr`, 서버/클라이언트 캐시, F12 GUID·section·key, 신규·기존 설치의 중복·잔존 파일을 포함한다. 실제 로더 결과가 근거 없는 추측이라면 `미검증`으로 기록한다. `JSON 검사 통과`, `C# 빌드`, `설치 ZIP`, `게임 표시`의 성공 범위를 섞지 않는다.


1. 수정 전 백업 또는 해시를 남기고 원본 키/source, 행 순서, 적용 조건, 사용자 수정사항을 비교한다. 이전 버전 전체 마이그레이션을 새 번역 작업마다 돌리지 않는다.
2. `python build/validate_translations.py`로 실제 번역 폴더를 검증한다. Python이 PATH에 없으면 설치된 실행 파일의 절대 경로를 사용한다.
3. config-ui 변경은 JSON 중복 속성, GUID, section+key, 원문과 치환 변수, 선택지의 실제 내부 값을 확인한다. 일반 번역 validator가 F12까지 검증한다고 가정하지 않는다.
4. 표시 규칙을 변경했다면 **테스트 원본이 실제로 존재할 때에만** `tests/LocaleDisplayContract`와 `tests/ServerDisplayContract`를 빌드·실행한다. **현재 소스 ZIP에는 두 테스트가 미동봉**되어 있으므로 실제 수행하지 못한 경우 `미실시(테스트 원본 없음)`으로 기록한다. 필요한 검증은 가능한 정적 검사와 C# 실제 빌드로 나누되, 이를 계약 테스트 통과로 대체해 주장하지 않는다. 부모 실제 값 비교와 `kr → kr-en → en → kr` 전환, 괄호 중복, 가격/탄약 장식, 원문 불일치를 확인한다. **현재 제공된 소스와 테스트를 직접 기준으로 삼는다.** 과거 `LOCALE_DISPLAY_1.7.16_KO.md`는 이 문서 ZIP에 없어 그 검증 기록을 확인했다고 주장하지 않는다. 전체 데이터 검사에 쓰는 분류 manifest와 실제 서버 snapshot은 현재 파일명·번역 데이터와 일치해야 한다.
5. 소스 변경은 기존 빌드 스크립트를 사용한다. JSON만 추가하면 새 번역 엔진이나 DLL 수정은 필요 없다. 사용자가 설치 패키지를 요청한 경우 기존 패키징 경로로 실제 최신 DLL/데이터를 묶는다.
6. 언어 정책 변경 시 클라이언트 DLL, 서버 DLL, translations/config-ui/native-locales를 함께 전달한다. 예전 DLL과 새 데이터의 혼합을 피한다.
7. 부모와 게임 설치본은 별도 설치 요청 없이 덮어쓰지 않는다. 인게임 미실행이면 “화면 검증 미완료”라고 명시한다.
8. 최종 보고에는 대상 모드/버전, 참고 원본, 사용한 채널, 변경 파일/개수, 코드 변경 필요성, 검증 결과, 실제 산출물, 미확인 항목만 간단히 적는다.

1.0.0부터 게임 실행 중 진단 파일을 생성하지 않는다. 상세 `unapplied`, `candidate_conflicts`, `missing_item_name_sources`는 **과거 개발용** `tests/LocaleDisplayContract`의 LOCALE_DIAGNOSTICS 검사에서 확인한 기록이 있다. **현재 소스에는 해당 테스트가 미동봉**이므로 지금 실행했다고 주장하지 않으며, 재실행은 테스트 원본이 확보된 경우에만 가능하다. 동일 키/원문을 여러 모드가 제공하면 첫 번째 일치 프로필을 선택하는 기존 충돌 정책이 있으며, 이를 특정 모드의 소유권을 완벽히 알아낸 결과라고 설명하지 않는다.

**17차 확정 오역·충돌 재발 검사:** `python build/audit_locale_integrity.py`를 실행한다. 같은 로케일 키와 같은 영어 `source`가 서로 다른 `translation`으로 등록된 경우에는 실제 영어와 문맥을 보고 일치시킨다. 영어 `source`가 서로 다른 후보는 임의로 합치거나 삭제하지 않는다. 명시된 단일 장탄수(`10-round`, `10발` 등) 불일치도 검사하며, 모델명 숫자와 용량을 혼동하지 않는다. 이 검사는 `python build/verify_release.py source`에도 포함된다. **정적 검사 통과는 인게임 적용 성공이 아니다.**

1.7.15 누락 수정에서 확인한 추가 검증: `unapplied`는 등록된 번역 행만 검사하므로 아예 등록하지 않은 새 퀘스트/상인 필드를 잡지 못한다. 실제 서버 영어/한국어 locale 및 설치된 모드의 퀘스트·아이템·상인 정의와 역방향으로 대조한다. `docs/tools/audit_runtime_coverage.py`를 사용하되 단축명/탄약명/로그 키를 전부 번역 누락으로 세지 않는다. 실제 raw locale을 `ClientLocaleModOverlay`에 입력하는 회귀 검증을 추가하고, 프로필 source만으로 만든 합성 테스트 통과를 실사용 검증이라고 보고하지 않는다. 원문 변경 시 목표의 대상·수량·장소·발견 조건도 함께 재검토한다.

카지노 번역 문구는 기존 모드 JSON을 유지한다. `small_ui`, `horse_racing_ui`, `casino_war_ui`, `server_messages` 채널을 합치거나 새 번역 시스템을 만들지 않는다.

클라이언트 화면은 `src/CasinoUiHooks.cs`가 Casino.Client의 확인된 TMP 텍스트 대입 지점에서 번역 후 한 번 대입한다. 텍스트가 반복 갱신되더라도 타이머·Update 화면 순회로 사후 번역하지 않는다. 전역 TMP setter, 입력 필드, 게임 상태 및 서버 전송 문자열을 패치하지 않는다. 일반 UI에 원문 괄호나 모드명도 추가하지 않는다.

새 문구는 먼저 기존 채널에 추가한다. 카지노 업데이트로 호출 경로가 달라졌다면 실제 DLL의 타입·메서드·텍스트 대입 수를 확인하고 전용 Targets만 최소 확장한다. **현재 소스에 미동봉된** `tests/CasinoWriteContract`는 원본을 확보한 경우에만 실행하여 원문 선대입 여부·언어 전환·비대상 입력을 검사한다. 확보하지 못한 경우 `미실시(테스트 원본 없음)`으로 기록하고 실제 소스 흐름·정적 검사 및 가능한 빌드 결과를 별도로 보고한다. DLL 검사 또는 대체 UI 테스트만으로 인게임 확인을 완료했다고 보고하지 않는다. 과거 `LOCALE_DISPLAY_1.7.18_KO.md`는 현재 문서 ZIP에 없으므로, 검증은 소스·테스트·실제 DLL을 근거로 한다.

1.7.19 가독성 보정은 `src/CasinoTextStyle.cs`가 담당한다. 카지노가 설정을 마친 후 렌더링 전에 한글을 직접 지원하는 폰트와 전용 머티리얼을 함께 적용한다. 번역 문구나 게임 전체 공유 폰트를 가독성 문제 해결 목적으로 변경하지 않는다. 원래 UI 색상과 영어 전환 복원을 유지한다.


## 1.0.0 성능·최소 로그 유지 기준

현재 `src/`의 진단·성능 정책을 따른다(과거 경위는 `docs/records/audits/LOCALE_DISPLAY_1.0.0_KO.md` 참고). 배포본에 자동 보고서·F12 발견 스냅샷·빈 템플릿·미번역 메일 수집을 재도입하지 않는다. 클라이언트/서버 로드 요약과 실제 실패의 최소 로그만 남긴다. 반복 경고는 `MinimalLog.WarnOnce`의 고정 식별자로 억제한다. 번역 본문이나 계속 바뀌는 문장을 식별자로 쓰지 않는다.

프로필을 공유하므로 로드된 원본 행을 변경하지 않는다. 카지노의 Queue는 텍스트가 같아도 유지하고 실제 폰트 비교는 생성 함수가 끝난 뒤 preWillRenderCanvases에서 한다. 부모 언어 조회 시점과 서버 동기화 순서를 임의로 바꾸지 않는다.

### 1.0.3 ArenaMode 독립 UI — 컴파일 전 검증 강화

ArenaMode 0.1.1의 독립 UI는 `src/ArenaModeUiHooks.cs`의 지정된 화면 출력 메서드와 `src/SmallUiLiteralHooks.cs`의 기존 리터럴 경로로 분리한다. 내부 판정 문자열을 직접 치환하거나 다른 모드·Unity 전체 TMP setter를 대상으로 패치하지 않는다. UI 훅 수정 뒤에는 `python build/verify_release.py source`로 C# 괄호 사전 검사까지 실행하고, 빌드 가능한 환경에서는 **반드시 실제 `dotnet build`까지 통과**해야 한다. Python 테스트·구문 균형 검사는 C# 컴파일 또는 게임 적용의 증거가 아니다. 해당 과거 재구현 이력은 `docs/records/patches/`에 보존한다. 이력은 현재 규칙이 아니므로 필요한 경우에만 참고하며, 이전 사용자 지시에 따라 원문은 임의로 변경하지 않는다. 현행 수정·검증은 현재 훅 소스와 실제 빌드 결과에 근거한다.

### Manimal Terminal 0.2.2 전체 경로 적용 및 검증 (2026-10-25)

기존 `seed_missing`은 영어 전용 퀘스트 101개와 업적 2개가 한국어 글로벌 로케일에서 **아예 빠졌을 때** 클라이언트가 정확한 원문 후보를 보충하는 제한적 보조책입니다. WTT가 같은 키에 **영어 fallback 값 자체를 이미 등록한 경우**와 별도의 Lightkeeper 대사 객체는 이것만으로 번역이 보장되지 않습니다.

서버의 `ManimalTerminalLocales.cs`는 원본 WTT 및 Terminal 등록 순서 다음에, 해당 키에 실제로 남은 영어 원문이 정확히 일치하는 경우만 `kr`/`kr-en` 글로벌 로케일을 변환합니다. Lightkeeper 대사 39개는 별도의 `TemplateTable.Dialogue.Elements` 두 객체에 한정해 한국어 언어 사전을 보충합니다. 기존의 다른 한국어·변경된 원문은 유지합니다. 클라이언트 자체 UI·컷신·에필로그·알림·F12는 각각 별도 훅이 필요하므로 서버 번역기 하나로 전체 한글화가 완료된다고 보지 않습니다.

원본 데이터/훅 구조 감사는 `python docs/tools/verify_manimal_full_scope.py --original <원본_압축해제_위치>`로 수행합니다. 이는 **정적 범위 검사**입니다. `docs/`와 무관하게 빌드되도록 이 감사 도구는 `BUILD_DISTRIBUTION.cmd`에 연결하지 않습니다. 신규 DLL의 실제 컴파일, 실행 순서, 언어 전환, 화면 렌더링이 확인되기 전에는 **전체 한글화 성공 미검증**으로 남깁니다.
