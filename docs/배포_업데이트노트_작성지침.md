# 배포 업데이트 노트 작성 지침

이 문서는 GPT가 사용자 공개용 `note/update.md`를 작성·수정할 때 따르는 규칙이다. **사용자가 직접 확정한 공개 양식과 삭제 기준을 우선**하며, 제외된 내용을 임의로 되살리지 않는다. 이 문서의 목적은 사용자에게 배포 버전의 변경점을 알리는 것이지, GPT와 진행한 개발·수정 내역을 공유하는 것이 아니다.

## 1. 공개 양식 — 제목 + 세 개 섹션만

1. 제목은 `# SPT Mod Korean Addon v[버전]`으로 작성한다.
2. 섹션은 **`### 설치 및 업데이트` → `### 신규 번역 지원` → `### 기존 번역 개선`** 순서만 사용한다.
3. 제목과 첫 섹션 사이에 **업데이트 날짜·SPT 버전·빌드 상태·소개 문구 등 별도의 부제목/메타데이터 줄을 넣지 않는다.** SPT 호환성과 버전은 작업 중 검증하고 `note/README.md` 등 필요한 문서에서 관리하되, 이 업데이트 노트의 고정 양식에는 추가하지 않는다.
4. `이전 업데이트`, `업데이트 이력`, `주요 변경 사항`, `추가 안내`, `알려진 문제`, `참고 사항`, `검증 결과`, `변경 파일` 등의 **추가 섹션을 자동 생성하지 않는다.** 사용자가 별도로 승인하지 않은 내용은 붙이지 않는다.
5. 기존 버전의 업데이트 항목을 `note/update.md` 맨 아래에 누적하지 않는다. 이 파일에는 **현재 게시할 버전의 내용만** 둔다.
6. `신규 번역 지원`과 `기존 번역 개선`에는 **직전 공개 버전에 없었고 이번 최종 공개 버전에 실제로 반영되는 변화만** 짧은 불릿으로 적는다. 사용자가 확정한 모드별 그룹·표현·순서를 우선하며 삭제된 모드·설명·수식어를 복원하지 않는다. 같은 모드의 신규 지원 항목이 이미 있다면 출시 전 내부 교정·수정 사항을 별도 개선 항목으로 중복 소개하지 않는다.
7. 코드 경로, C# 훅 이름, 개발 노트, 작업 로그, 테스트 건수, 빌드 과정, 소스 ZIP 관련 문구, 사용자 PC 경로는 공개 글에 넣지 않는다. 제외한 모드도 굳이 언급하지 않는다. **같은 버전 출시 전의 버그 수정·번복·자간 조정·문구 재작성·빌드 문제 해결은 작업 과정일 뿐 별도의 공개 업데이트 항목이 아니다.** 단, 이전에 실제 공개한 버전에서 발생한 문제를 이번 공개본이 해결했다면 사용자에게 중요한 수정으로 포함할 수 있다.

## 2. 공개 버전 간 차이만 기록 — 필수 판정

1. **비교 기준을 먼저 확정한다.** 마지막으로 사용자에게 실제 공개·배포한 버전과 이번에 공개할 최종 버전을 비교한다. 파일명이나 작업 중 임시 버전을 기준으로 변경 내역을 누적하지 않는다. 마지막 공개 버전이 확인되지 않으면 추측해서 변경 사항을 쓰지 않고 확인을 요청한다.
2. **작업 기록과 공개 변경 내역을 혼동하지 않는다.** 같은 버전에서 여러 차례 수정·재수정했거나 사용자와 함께 고친 중간 결과는 `docs/records/work-history/`의 작업별 인계 기록에서만 관리한다. 공개 노트에는 그 과정이 아니라 최종 사용자에게 추가되거나 달라지는 기능·번역만 기재한다.
3. **각 항목을 출시 기준으로 판정한다.** `이전 공개본에는 없고 최종 배포본에는 있는가?`, `사용자에게 실제 공개할 가치가 있는 내용인가?`, `기존 불릿과 중복되지 않는가?`를 확인한다. 어느 하나라도 충족하지 않으면 내부 작업 항목을 공개 노트로 옮기지 않는다.
4. **수정할 때도 자동으로 불릿을 추가하지 않는다.** 모든 번역/코드 작업의 끝에는 `docs`·`records`·`note`의 갱신 필요성을 점검하지만, 아직 같은 공개 예정 버전의 개발 과정이라면 `note/update.md`의 새 항목 추가가 의무는 아니다. 공개 버전 변경점이 확정되거나 기존 초안 내용이 잘못된 때에만 최종 차이 기준으로 갱신한다.
5. **사용자가 제거한 세부 사항을 되살리지 않는다.** 기록으로 남길 필요가 있으면 별도의 개발 인계 기록으로 처리하며, 삭제된 문장을 공개 노트에 다른 표현으로 다시 삽입하지 않는다.

## 3. 설치 안내의 기본 문구

기본 설치 섹션은 아래 **세 단계, 폴더 전체 삭제 불필요 안내, 필수 모드 이름과 전체 URL**을 따른다. 단, 현행 공개 문서에 이미 기재된 **구버전 잔존 파일의 개별 삭제 예외**는 해당 파일의 존재·충돌 여부를 확인해 별도로 취급한다. 임의의 백업·폴더 전체 삭제·수동 DLL 설치·게임 경로 안내를 추가하지 않는다.

```markdown
### 설치 및 업데이트
1. 게임과 서버를 종료합니다.
2. 배포 ZIP의 `BepInEx`, `SPT_Runtime` 폴더를 **SPT 설치 폴더**에 압축 해제합니다.
3. 기존 파일과 겹치면 **모두 덮어씁니다.**

기존 애드온이나 `translations` 폴더를 삭제할 필요는 없습니다.

**필수 모드: SPT Korean Project Locale Patcher**

https://sp-mod.com/mod/1629/spt-korean-project-locale-patcher
```

**이 문구를 그대로 사용할 사전 검사:** (1) 새 설치 모의 폴더에 실제 빌드 ZIP 적용, (2) 지원하는 기존 설치를 모의하여 같은 ZIP 덮어쓰기, (3) 두 환경의 파일·프로필 로딩 대상·잔존 구형 파일·충돌·누락 비교, (4) 구버전 삭제 지시가 있는 경우 **구형 파일이 덮어쓰기로 제거되지 않는지** 확인한다. 두 환경에서 필요한 정상 결과가 다른데도 '덮어쓰기만으로 업데이트 가능'이라고 단정하지 않는다. ZIP 소스 파일을 설치용이라고 안내하지 않는다.

**검증된 예외 처리:** 특정 구버전 프로필이 남아 현행 번역 선택을 방해한다면 파일 전체 경로·영향·삭제 필요 여부를 기록한다. 사용자 승인 없이 전체 `translations` 폴더 삭제나 다른 모드 파일 삭제를 안내하지 않는다. 이미 현행 사용자 안내에 특정 개별 파일의 정리 지시가 있다면 그 사실·범위를 재확인하고 불필요하게 확대하지 않는다. **새로운 설치 예외나 승인된 공개 양식 변경은 사용자 확인 후 필요한 문구만 반영**한다.

단, 실제 배포 구조·설치 방식·필수 모드가 바뀐 경우에는 사실을 확인하고 사용자의 새 승인을 받아 **필요한 문구만** 변경한다. 기존 설치 방법과 다른 상황을 묵살하라는 뜻은 아니다.

## 4. 다음 버전용 최소 틀

```markdown
# SPT Mod Korean Addon v[버전]

### 설치 및 업데이트
1. 게임과 서버를 종료합니다.
2. 배포 ZIP의 `BepInEx`, `SPT_Runtime` 폴더를 **SPT 설치 폴더**에 압축 해제합니다.
3. 기존 파일과 겹치면 **모두 덮어씁니다.**

기존 애드온이나 `translations` 폴더를 삭제할 필요는 없습니다.

**필수 모드: SPT Korean Project Locale Patcher**

https://sp-mod.com/mod/1629/spt-korean-project-locale-patcher

### 신규 번역 지원
- **[모드 이름]:** [실제 새 번역 내용]

### 기존 번역 개선
- **[모드 이름]:** [실제 기존 번역 개선 내용]
```

이 틀의 대괄호만 확정된 항목으로 교체한다. 사용자가 현재 버전에서 승인한 문구를 멋대로 다시 구성하지 않는다. 해당 버전에 실제 변경이 없는 범주를 억지로 채우거나 사실이 아닌 번역을 만들어 넣지 않는다.

## 5. 작성 전 확인과 마지막 문서 갱신

- **공개 글에 넣을 사실:** 직전 실제 공개본과 최종 배포본의 차이, 신규·개선 번역의 대상 모드와 범위, 사용자 체감 변경, 설치 시 덮어쓰기 가능 여부, 필수 모드를 확인한다. 수량은 실제 적용 항목과 대조한다. 같은 버전 내 개발 과정은 차이로 계산하지 않는다.
- **변경 발생 시 함께 갱신:** 작업 마지막에 `docs/번역작업안내서.md`, `docs/모드번역_작업절차.md` 등 GPT 지침의 갱신 필요 여부, `note/README.md`의 설치·호환 정보, `note/번역지원모드목록.md`의 지원 범위를 확인한다. 변경이 필요한 문서만 수정한다.
- **형식 최종 확인:** 제목 1개와 지정된 `###` 섹션 3개만 있는지, 날짜·SPT 부제목·이전 버전 이력·추가 섹션이 없는지, 사용자가 제거한 문구가 재등장하지 않았는지, 출시 전 수정 기록이 잘못 포함되거나 중복 소개되지 않았는지 검사한다.
- **덮어쓰기 검증 기록:** 신규 설치/기존 덮어쓰기 각각 `입력 ZIP/설치 전 파일 목록/설치 후 파일 목록/잔존 구형 파일/로드 충돌/판정/증거 경로`를 남긴다. 모의 파일 대조 통과는 실제 SPT에서의 로딩 성공과 구분한다.
- **완료 상태 구분:** 검증되지 않은 번역이나 아직 빌드에 반영되지 않은 작업은 확정된 출시 변경 사항으로 쓰지 않는다. 필요하면 공개 노트 밖의 작업 보고에서 상태를 설명한다.

**우선순위:** 사용자가 최신으로 확정한 공개 문구 > 이 문서의 최소 틀 > 과거 버전의 노트 및 개발 자료.
